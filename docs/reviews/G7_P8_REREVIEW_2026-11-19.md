# G7 visual RE-review, P8 payments, finance and workspace screens (2026-11-19)

Independent reviewer (did not build or fix the UI). No application code, CSS, lang, tests or config was changed and nothing was committed. Re-review of `docs/reviews/G7_P8_REVIEW_2026-11-19.md` (defects D1-D16). Same screen list and same six-dimension rubric (Ref, Vis, RTL, Resp, Sta, Con; 1-5; pass threshold mean >= 4.5 and every dimension >= 4). Screenshots: `tests/Browser/screenshots/G7-P8-rereview/<screen>-<ar|en>-<1440|390>[-dark].png` (full page, 120 PNGs; `tabbar-*` are viewport-only 390 captures).

**Result: no screen reaches 4.5. G7 stays OPEN for P8.** Scores moved up by roughly 0.3 to 0.6 on the public and checkout screens and 0.1 to 0.3 on staff screens; the highest per-capture score is 4.1.

## Method and environment
- Scratch SQLite DB in the scratchpad (never `database/database.sqlite`), `migrate --force`, `demo:seed`, `APP_ENV=local`, `php artisan serve --port=8099`, **repo-default `CACHE_STORE=file` (not overridden)**, `npm run build` run once (public/build was older than `checkout/order.blade.php` and `User.php`). Server stopped at the end.
- Seeded through the app Actions (tinker): 3 refunds (`RequestRefund`/`ApproveRefund`/`ExecuteRefund`: one executed, one approved, one pending), 3 ledger adjustments (`RecordLedgerAdjustment`), an instructor payout profile (`SavePayoutProfile`), 2 October statements (`GenerateInstructorStatement`) and 1 draft settlement batch (`CreateSettlementBatch`). Data-only tweak in the scratch DB: the three adjustment ledger rows were back-dated to 2026-10-15 so a statement for an ended month could be frozen (no Action sets `earned_at`). The demo seed already contains an active subscription for Nour (plan order 5), so no new subscription was created.
- Staff 2FA: known TOTP secret set on admin/finance/instructor users in the scratch DB only; device/session tables cleared.
- Tooling deviation: pages were driven and captured with Playwright Chromium (node script, repo `node_modules`), not the built-in `mcp__Claude_Browser__*` pane, because the pane cannot write PNG files into the repo. The pane tools were loaded but not used for the screenshots.
- Viewports 1440x900 and 390x844, Arabic (`dir=rtl`) and English (`dir=ltr`), light theme; dark theme for catalog, checkout order and admin dashboard. Anonymous public pages use the `/ar` and `/en` prefixes (the plain `locale` cookie is not honoured for guests; logged-in users follow `users.locale`).
- Accounts: Omar (learner, EN-leaning demo user) for course/checkout/payments, Nour for the active subscription, admin, finance, Karim (independent instructor).
- How I read: for every screen I opened a contact sheet (AR 1440, EN 1440, AR 390, EN 390) and zoomed single captures where something looked wrong (subscription dates, reports with data, tab bar). No pixel measurements or contrast ratios were taken; scores are visual judgements. Anything I did not open is marked "not inspected".
- Reference coverage as in the first review (05, 06, 11, 10, 01, 14 where they exist; sibling screens otherwise, lower confidence).
