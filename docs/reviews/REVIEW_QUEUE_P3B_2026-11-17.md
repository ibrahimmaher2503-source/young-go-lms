## Findings

### B01 — BLOCKER — OCR skips nonempty pages that fail quality checking (T-P3-09)

`app/Domain/AI/Ingestion/IngestCurriculumDocument.php:91` attempts OCR only when the repaired text has fewer than `min_page_chars`. It scores the page only afterwards at line 96. A long corrupted text layer therefore never reaches OCR, even when an OCR provider could recover it. AI spec §6.3 explicitly requires fallback for a page with no text layer **or one that fails quality checking**. The current A2 test supplies an empty string and cannot detect this case. Score the text before choosing fallback and cover a nonempty low-quality page. Also inspect `app/Domain/AI/Ingestion/QualityScorer.php:17`: punctuation/symbols count as readable, so a sufficiently long punctuation-only page receives a high score despite containing no Arabic/Latin words (AI §6.4).

### B02 — BLOCKER — Extracted-text edits have no recoverable version history (T-P3-09)

`app/Domain/Media/Actions/EditExtractedPage.php:42` overwrites `approved_text`. The audit at line 44 stores only hashes and lengths; `lesson_document_pages` has one row per document/page (`database/migrations/2026_11_17_200000_create_ai_tables.php:23`). Multiple corrections to the same uploaded PDF cannot be recovered or distinguished as text revisions. AI spec §6.5 requires edits to be **versioned and audited**. The upload's document version stays unchanged across every edit, so binary PDF versioning alone does not satisfy this requirement. Keep revision evidence without putting full AI conversations into audit logs.

### B03 — BLOCKER — Approval can silently overwrite a concurrent saved correction (T-P3-09)

`app/Domain/Media/Actions/ApproveCurriculumDocument.php:45` reads page text and prepares embeddings before taking the document lock at line 50, then writes that old text back at line 56. Interleaving: approver A reads text; approver B saves a correction under the document lock in `EditExtractedPage.php:35`; A then locks the still-awaiting document and overwrites B's correction with the earlier text, also indexing the earlier text. Status validation does not detect a changed page revision. This violates A3 and AI §§6.5–6.7's approved-source integrity. Retain the network call outside long-held locks, but require an unchanged source revision/hash when committing, or recompute safely.

### B04 — BLOCKER — Document mutation Actions omit course object authorization (T-P3-09)

`ApproveCurriculumDocument.php:37`, `EditExtractedPage.php:25` and `ApproveKeyTerms.php:24` check active status plus `lesson_document.approve`, but do not check the document's course/assignment. The page checks the course update gate only in `app/Filament/Resources/Courses/Pages/ReviewCurriculumDocument.php:47`; subsequent save/approve calls load the document but only compare course IDs (`:115`). Thus a mounted page whose instructor loses manage scope can still mutate documents while retaining approval permission. Direct domain callers with this permission can also target an unrelated instructor's course. R2 requires server-side object scoping on each mutation, not only initial page mount. Existing forbidden tests omit a permission-bearing wrong-owner/revoked-scope actor. Reuse the course policy in the Actions and exercise both cases.

### B05 — BLOCKER — Required AI evaluation gate was deferred without a governing exception (T-P3-09, T-P3-10)

`agents/tasks/P03.md:192` and `:213` require G8 for these tasks; `agents/VERIFICATION_GATES.md:16` applies it to AI, prompts and extraction. `agents/PROGRESS.md:477` and `:483` instead say G8 belongs to T-P7-05. No exception was found in the governing Decision Register or ED-001..032. A task implementation note cannot waive a verification gate. Keep closure blocked pending the required evaluation evidence or an explicit governing decision changing applicability; a fake provider and an injection fixture do not establish eval thresholds. Real provider/model remains legitimately OPEN (O-014); do not invent credentials or live-provider evidence.

### B06 — BLOCKER — Assessment association supports sections only (T-P3-11)

`app/Domain/Curriculum/Actions/ManageAssessmentItems.php:28` requires a CourseSection and persists only that section/course at line 55. `database/migrations/2026_11_17_170000_create_curriculum_tables.php:39` makes section_id mandatory; Quiz and Assignment expose only the curriculum-item relationship, with no lesson association. The task goal and PRD §§12–13 require association at course, section **or lesson** level. ED-002 settles the single ordering source, but does not remove these association requirements. A1's mixed-section order test is useful and covered; it does not establish the other required placement modes. Resolve the association design under the existing ordering system rather than inventing a second ordering list.

### B07 — BLOCKER — Duplicated rich lessons retain original resource IDs (T-P3-12)

`app/Domain/Catalog/Actions/DuplicateCourse.php:144` copies rich-content JSON unchanged. It creates new resource rows at line 158 without recording/remapping old IDs. `app/Domain/Content/RichContent.php:223` deliberately resolves an image resource only within the new lesson. Therefore a copied rich lesson with an image block still points at the source lesson's resource ID and renders no image. The existing lifecycle test checks copied JSON/files but does not render an image in the duplicate. A1 requires an independent draft including its lesson/resources; remap the structured image references to copied resources and verify rendering after deleting the source.

### B08 — BLOCKER — Safe-delete history integration is stale after P6 (T-P3-12)

`app/Providers/AppServiceProvider.php:98` registers only EntitlementHistory, ProgressHistory and CohortHistory under `course.history`. Existing quiz attempts/submissions and certificates have no checker. `DeleteCourse.php:55` consequently does not report those blockers before attempting the deletes at lines 85–86. Quiz attempts use `restrictOnDelete` (`database/migrations/2026_11_17_340000_create_quiz_attempts_tables.php:19`), so this case currently reaches an unhandled DB failure rather than the localized history-blocked result. This finding does **not** claim the quiz FK silently deletes attempts. PRD §9.5 and task A2 require safe preservation with a deliberate refusal/archive path; register current history owners and test the integration. The PROGRESS note at line 517 explicitly identified this future integration requirement, and those tables now exist. Also protect the check/delete decision from concurrent creation of history rather than relying on a pre-transaction check alone.

### B09 — BLOCKER — Subtitle rollback restores rows pointing to deleted files (T-P3-14)

`app/Domain/Media/Actions/ManageSubtitleTracks.php:71` deletes the previous file inside the replacement transaction, before audit success at line 73. If audit fails/throws, DB rollback restores the old track but its file is already gone; the catch also deletes the newly uploaded file. Removal repeats the problem at lines 104–105. R2/R5 require safe file handling and meaningful failure tests. Defer destructive old-file cleanup until the DB transaction commits. Add an audit-failure regression for replace and remove; the current happy-path cleanup test does not cover rollback.

### B10 — BLOCKER — Restricted block authoring is incomplete and images bypass library-only policy (T-P3-15)

`app/Filament/Resources/Courses/Pages/ManageCurriculum.php:428` exposes formatting/table controls but no callout, library-image or allowlisted-embed authoring controls. Render support alone is insufficient for the task's instructor authoring goal and ED-003 block set. Separately, `RichContent.php:223` accepts any image resource of the lesson, including directly uploaded materials with no library_item_id; ED-003 and the task require **images from the library only**. Existing RichContent tests intentionally accept lesson materials and therefore assert a broader policy. Keep the signed/private access check and same-lesson scoping while implementing the required library selection/origin rule. No AI indexing of text lessons was found in the assigned implementation, consistent with D-018.

### S01 — SHOULD — Mixed malformed/valid VTT files pass validation (T-P3-14)

`app/Domain/Media/VttValidator.php:36` skips every line that fails the timing regex, then accepts the file if any other valid cue exists at line 47. For example a WEBVTT file with a valid `00:00.000 --> 00:01.000` cue followed by `00:99.000 --> 00:02.000` is accepted because the malformed timestamp line is ignored. The current invalid-timestamp dataset checks a file with no other valid cue, so it does not catch mixed input. A1 requires invalid VTT rejection; recognize cue blocks and reject malformed timing/cue structure while retaining legitimate NOTE/STYLE/REGION handling where supported.

### S02 — SHOULD — Library table performs two count queries per row (T-P3-13)

`app/Filament/Resources/Library/LibraryResource.php:86` calls `LibraryItem::referenceCount()` for each rendered row; `app/Models/LibraryItem.php:42` runs two separate count queries. This adds 50 queries to a 25-row page. R3 prohibits N+1 lists. Load reference counts with the resource query while retaining permission scoping; use the same authoritative reference semantics for delete.

### S03 — SHOULD — Ingestion writes occur outside Actions (T-P3-09)

`app/Domain/AI/Ingestion/IngestCurriculumDocument.php:40`, `:138` and `:167` write document/page state outside `app/Domain/*/Actions`. This is a command invoked by a queued job, rather than a pure ingestion helper. AGENTS rule 4 / R3 require business mutations in Actions. Reuse the ingestion helpers but put the orchestration mutation under the existing Actions convention; do not introduce a parallel service layer.
