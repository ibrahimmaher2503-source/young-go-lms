## What was built
- `App\Domain\InstructorFinance\PayoutMethod`: cases Bank (`bank`, label "bank transfer"), Wallet, Instapay (`instapay`), plus LEGACY Cash and Other (display only). `allowedFor(string $currency)` returns EGP: Bank, Wallet, Instapay; SAR: Bank; any other currency: empty. `isAllowedFor`, `acceptsReference($ref)` (bank/wallet: 3..64 chars, Instapay: 6..64; letters, digits, `- _ / .` and inner spaces, first char alphanumeric), `referenceErrorKey()`.
- `RecordSettlementPayout`: the length check (`settlements.reference_invalid`, 3..64) runs first, then the per-method format (`settlements.reference_invalid_bank|wallet|instapay`), then the date; inside the transaction: paid-line idempotency, `state_invalid`, then `settlements.method_not_allowed` (field `method`) when the method is not allowed for `Settlement::currency`. A refused call changes nothing (entries stay `approved`, no audit row, item unpaid).
- `SettlementResource` record-payout action: the Method select options are `PayoutMethod::allowedFor($settlement->currency)` with `settlements.method_*` labels and a currency helper text (`method_help_egp|sar`); an unknown value raises the same refusal.
- Payout profile: `PayoutProfile::INSTAPAY`; `SavePayoutProfile` accepts method `instapay` with `instapay_address` (`name@bank`: 3..64 chars of `a-z0-9._-` before the `@`, or a phone `+?` 8..15 digits; lower-cased, spaces removed; error `instructor_onboarding.payout.errors.instapay_invalid`). Stored inside the existing encrypted `details` payload (no migration). `PayoutMask::identifier` masks it (last four characters). `RevealPayoutProfile` returns it only with `payout_profile.reveal` and audits `payout_profile.revealed` with the method only. `MyPayoutProfile` form has the Instapay option and field.
- Statement PDF (`StatementPdf::data` keys `payoutMethods`, `currency`; view `statements/pdf.blade.php`) prints "Payout methods for EGP/SAR: ..." in the PDF locale. The settlement details view shows `settlements.method_<value>` for each paid line.
