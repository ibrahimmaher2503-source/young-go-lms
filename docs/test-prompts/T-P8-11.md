## What was built
- Contract `PaymentGateway::listTransactions(CarbonImmutable $from, CarbonImmutable $to): list<VerifiedPaymentEvent>`. Fake: returns every transaction queued with `queueTransaction()` (ignores the window), records a `listTransactions` call, honours `failNext()`. Null: always `[]`. Paymob: `[]` without complete credentials (assert with `Http::fake()` that no request is sent); with credentials it authenticates then pages `/api/acceptance/transactions`, keeps rows with `created_at` inside the window, stops at an all-older page, `next` null, or 50 pages; an HTTP failure throws `PaymentGatewayException` (no secret in the message).
- `Actions\ReconcilePayments` (`__invoke(CarbonImmutable $day): PaymentReconciliation`). Window = that day, start to end of day. Per gateway transaction (pending ones are skipped, neither matched nor mismatched):
  - no attempt with that reference (gateway + `reference`) -> `unmatched_transaction`, reason `no_attempt_for_reference`;
  - refunded or voided -> `refunded_at_gateway`, reason `refunded` / `voided`;
  - success with amount or currency different from the attempt -> `amount_mismatch` (`amount_or_currency_differs`);
  - success while the attempt is not `succeeded` or the order not `paid` -> `status_mismatch` (`paid_at_gateway_not_locally`);
  - success equal in amount, attempt succeeded, order paid -> counted `matched`;
  - failed at gateway while our attempt is `succeeded` and the gateway shows no success for that reference -> `status_mismatch` (`failed_at_gateway_paid_locally`); a failed try beside a success for the same reference is just matched.
  - Local attempts `succeeded` with `updated_at` in the window and no transaction at all for their reference -> `missing_at_gateway` (`not_in_gateway_listing`).
  - Run row unique per (gateway, `run_date`): `transactions_seen`, `local_attempts` (attempts created in the window), `matched`, `mismatched`, `completed_at`; a re-run updates it. Mismatch unique per (gateway, `mismatch_key` = `type:transactionId` or `type:reference`): a re-run adds no row and does not reopen a reviewed one.
  - Audit (`audit` log, subject = run or mismatch): `payment.reconciliation_completed` per run, `payment.reconciliation_mismatch_found` once per new mismatch (no secrets, no card data), `payment.reconciliation_mismatch_reviewed`. Event `PaymentReconciliationCompleted` is dispatched after the run is stored.
  - A gateway failure (`failNext()`) throws `PaymentGatewayException` and writes no run or mismatch.
- `Actions\ReviewPaymentMismatch(User, mismatch)`: needs an active user with `payment.approve_manual` (else `AuthorizationException`); sets status `reviewed`, `reviewed_by`, `reviewed_at`; a second call is a no-op with no second audit row.
- Command `payments:reconcile {--date=}` (scheduled `dailyAt('04:30')`, name `payments:reconcile`, `withoutOverlapping`): default date is yesterday; an invalid date exits 2; a gateway that is not configured (Null, `PAYMENTS_GATEWAY=null`) prints "not configured; reconciliation skipped", exit 0, no rows; a gateway error exits 1; success prints the counts.
- Page `PaymentReconciliationPage` (slug `payment-reconciliation`, admin and finance panels, `canAccess` = `payment.view` or `payment.approve_manual`): last-run tiles, filter open/reviewed/all via `$filter`, list capped at 100, Livewire `markReviewed($id)` (only with `payment.approve_manual`; with `payment.view` alone there is no button and a forced call shows a denied notification). Views carry `data-payment-reconciliation`, `data-mismatch-table`, `data-mismatch="{id}"`, `data-open-count`, `data-mismatch-empty`.

## Acceptance to cover
- A1 Report only: for every mismatch type, the order status, attempt status, entitlement rows and `payment_events` count are unchanged after the run (never auto-change order state).
- One test per mismatch type above, plus the clean-match case (matched 1, mismatched 0), the pending-skipped case and the failed-beside-success case.
- Idempotency: run the same day twice -> one run row, one row per mismatch, one `mismatch_found` audit per mismatch; mark one reviewed, re-run -> it stays reviewed.
- Failure: `failNext()` -> exception, 0 rows; the command returns 1.
- Command: default date is yesterday (use `Carbon::setTestNow`), `--date=2026-11-10` honoured, invalid date, unconfigured gateway skip; the schedule lists `payments:reconcile` at 04:30 (inspect `app(Schedule::class)->events()`).
- Gateways: Null returns `[]`; Paymob without credentials returns `[]` and makes no HTTP call; with credentials and `Http::fake()` the window filter and the paging stop rules work and the token is sent only in the header.
- Permissions: `payment.view` sees the page (no button); `payment.approve_manual` can mark reviewed; a learner or user with neither gets 403; an inactive account cannot review. Admin and finance panels both list the page.
- AR/EN: `lang/{ar,en}/payment_reconciliation.php` have the same keys including every `types.*` and `reasons.*` value used; the three audit keys exist in `lang/{ar,en}/audit-events.php`; render the page in both locales (no raw keys). `app:check-translations`, `app:check-rtl` and `tests/Arch` pass.
- Known gaps (not built): the real Paymob listing endpoint is unverified against live docs (B-07), no CSV export, no review notes, no alert on new mismatches, no resolution actions (finance acts on orders through the existing manual flows).
