## What was built

- `SaveCourseWizard` (now `LAST_STEP = 7`: 1 Basic, 2 Information, 3 Pricing, 4 Media, 5 SEO, 6 Custom, 7 Finish; signature unchanged: `($actor, $data, $course, $step, $complete)`):
  - Pricing fields (only for `canSetPricing` users, otherwise `AuthorizationException`): `access_duration_days` (int 1..3650 or empty), `bundle_eligible`, `manual_access_allowed`; changes are audited in the existing `course.pricing_changed` event (before/after include the changed settings).
  - Media: `cover_image` (an uploaded file, or `[uuid => file]`; an empty array removes; a string equal to the stored path is "no change"; any other string is a `ValidationException` on `cover_image`) and `promo_video` `{provider, url}` where provider is `youtube`, `vimeo` or `external_url` (validated through `MediaProviders`/`SourceUrl`, https only; empty provider and url clears it; errors on `promo_video.provider` / `promo_video.url`).
  - SEO: `seo_title`, `seo_description`, `seo_keywords` (each `{ar,en}`, max 160/320/300) and `canonical_url` (https URL, max 500, empty becomes null).
  - Custom: `custom` = map field key => value (or `{ar,en}` for translatable text); required fields enforced only when step 6 is passed with `$complete = true`.
  - A course in `pending_review` cannot be saved by a user without `course.publish` (`course_wizard.review.locked_pending`).

- `CourseCustomValues` (validation/clean/public display), `SaveCourseCustomField` (admin only: `panel.admin.access` + `course.publish`; key `/^[a-z][a-z0-9_]{1,59}$/`, unique, immutable after create; type text/textarea/number/select/toggle/url/date; label AR or EN; select needs 2+ options; min/max; visibility public|internal; translatable; active; sort; audit `course_custom_field.saved`). - Actions: `SubmitCourseForReview($actor, $course)` (needs `update`; draft only; submit blockers; sets `pending_review`, `submitted_at`, clears `review_reason`; audit `course.submitted_for_review`), `ApproveCourse($course, $actor, $note)` and `RejectCourse($course, $actor, $reason)` (mutations behind `RecordReviewDecision`; pending only; approve needs publish checks; reject needs a reason and returns the course to `draft` keeping `review_reason`; both dispatch `CourseReviewed` after commit), `ReviewCourse($actor, $course, 'approved'|'rejected', $reason)` (wraps `RecordReviewDecision` with ability `publish` and prefix `course.review`, audit events `course.review.approved` / `course.review.rejected`, reason min 10 chars on reject), `PublishReadyCourse($actor, $course)` (Finish "Publish": `publish` policy + all checks, audit `course.published`).
- Notifications: listener `NotifyInstructorsOfCourseReview` sends `course.approved` / `course.rejected` (new matrix rows, mandatory, group `course_review`) to the course's instructors and `owner_instructor_id`; rejection body contains the reason.
- Enforcement: `GrantEntitlement` sets `ends_at = starts_at + access_duration_days` for sources free, purchase and bundle when no end date is passed (manual and subscription sources are unchanged) and refuses `EntitlementSource::ManualGrant` when `manual_access_allowed` is false (`entitlements.manual_not_allowed`, key `course`); `SaveBundle` refuses a course with `bundle_eligible = false` (`bundles.courses_not_eligible`, key `items`).

Public course page shows the cover (`courses.cover_image` before the category image) and a `[data-section=custom-fields]` card with public custom fields.

## Acceptance
- A1 Independent course: an `instructor_independent` creates a course through the wizard (owner independent), adds a section with a lesson, passes steps 1-6, then `SubmitCourseForReview` makes it `pending_review` (audit `course.submitted_for_review`; the instructor cannot save it while pending; `PublishCourse`/`PublishReadyCourse` by the instructor is forbidden). An admin with `course.publish` and `course.approve` and `ReviewCourse(..., 'approved')` makes it `published` (needs pricing set by the admin first, otherwise `ValidationException` key `status`), audit `course.review.approved`, instructor notification `course.approved`. Reject without a reason or with fewer than 10 chars fails (course stays pending, no audit); a valid reject returns to `draft`, stores `review_reason`, audit `course.review.rejected` with the reason in context, notification `course.rejected` contains the reason, and the instructor can edit and resubmit. An admin without `course.approve` cannot approve an independent course (`AuthorizationException`); a non-pending course cannot be approved/rejected; an academy admin can use `PublishReadyCourse` directly. Submit without a lesson, missing basic data or an empty required custom field is refused with the blocker names. Table row actions `approve`/`reject` appear only for pending courses and only for users who pass `publish` (Livewire test of `ListCourses`, reject modal requires reason).
- A2 Pricing settings: `access_duration_days`, `bundle_eligible`, `manual_access_allowed` save and reload through the wizard (step 3); invalid values (0, 3651, 1.5, text) fail on the field; a user without pricing rights sending any of them gets `AuthorizationException` and the Livewire edit form does not include them. Behaviour: a free enrolment and a paid order grant on a course with `access_duration_days = 30` end 30 days after the start; a null duration stays lifetime; a manual grant is unaffected by the duration; with `manual_access_allowed = false` a manual grant throws and a paid or free grant still works; a bundle containing a course with `bundle_eligible = false` cannot be saved (`bundles.courses_not_eligible`), an eligible one can. The existing A2 pricing test and the Saudi lock stay green.
- A3 Custom field validation enforced: create definitions through `SaveCourseCustomField` (admin only; an instructor gets `AuthorizationException`; duplicate or malformed key fails; select with one option fails; audit written). Values: text max/min length, number min/max and numeric, select only from options, url https only, date `Y-m-d`, toggle boolean, translatable text `{ar,en}`; unknown keys are dropped; required enforced only when step 6 is passed (draft save is lenient); stored values survive when a key is not submitted; inactive definitions are not editable but their stored value is kept. Public page: only `public` fields with a value render (escaped, per locale for translatable), internal ones never appear.
