## Behaviour to cover
1. `SubmitManualPaymentProofRequest` (P2): a POST to `manual-payments.store` with empty fields returns errors per field; the messages use the lang attribute names, never the raw field name. EN: `The sender name field is required.`, `The transfer date and time field is required.`, `The transfer proof file field is required.`. AR (locale `ar`): messages contain no ASCII letters (no `payer name`, `transferred at`, `proof`). Both locales have every `manual_payment.attr_*` key, plus `validation.regex` and `validation.file`. A user who is not the payer of the order gets 404 even with invalid input (the request's `authorize()` runs before validation).
2. Date input (P1): `#transferred_at` renders as `type="text"` (no `datetime-local`), has `placeholder` from `manual_payment.date_placeholder`, and the hint `manual_payment.transferred_at_hint` is linked with `aria-describedby="transferred_at-help"`. The server accepts `18/11/2026 14:30`, `18/11/2026 14:30:05`, `18/11/2026` (stored at 12:00) and the ISO forms (`2026-11-18 14:30:00`, `2026-11-18T14:30`); it rejects `31/02/2026 10:00`, `18/11/2026 25:99` and free text with `manual_payment.date_format_invalid` under `transferred_at`; a parsed future time or one older than `manual_payments.max_age_days` still gives `transfer_date_invalid` from the Action. The stored `transferred_at` equals the typed wall time in `app.timezone`. Existing tests that post `Y-m-d H:i:s` must still pass.
3. Filament lists (T1/W2): for coupons, bundles, plans, subscriptions, refunds, ledger, statements, settlements and manual payment proofs the table root carries `yg-compact-table`; the columns hidden below `md` have `visibleFrom('md')` (assert via `getColumn(...)->getVisibleFrom()` or the rendered `fi-hidden`/`md:table-cell` classes) and exactly three columns stay visible on phones (coupons: code, name, status; bundles and plans: name, price, status; subscriptions: learner, plan, state; refunds: payer, amount, status; ledger: date, amount, status; statements: number, net; settlements: reference, total, status; proofs: order, amount, status). Refunds columns `reason`, `requested_by`, `created_at` are toggleable and hidden by default; `reference`, `order.reference`, `payer`, `amount_minor`, `method`, `status` are visible by default at md+.
4. Row actions: each of those tables (except statements and ledger) renders one action group (`heroicon-m-ellipsis-vertical`) placed before the cells (`RecordActionsPosition::BeforeCells`). Every existing action name still works through the group (`callTableAction('approve' | 'reject' | 'execute' | 'edit' | 'allocation' | 'details' | 'cancel' | 'payout')`) with the same authorisation, so a user without `payment.approve_manual` or `payment.refund` still cannot run it.
