## Acceptance
- A1 Tampered signature rejected: wrong, missing and empty signature, and an altered payload with the old signature, give 401; `payment_events` stays empty, order and attempt unchanged, no entitlement, no audit row, no `PaymentVerified`. Nothing is read from the body before verification (swap the gateway with a spy that throws and assert the action did not touch the DB).
- A2 Amount/currency mismatch flagged: signed success with a different amount, or currency `USD`, returns 200, stores an event with outcome `flagged`, reason `amount_mismatch`, order stays `pending`, no entitlement, attempt not succeeded, `payment.flagged` audit row and `PaymentFlagged` dispatched.
- A3 Duplicate/replayed webhook: the same signed success posted 3 times (also concurrently-simulated by calling the action twice) gives one `payment_events` row, order `paid`, exactly one `entitlements` row (source `purchase`, `source_ref` `order:<ref>`), one `order.status_changed` audit, one `payment.verified` audit, `PaymentVerified` dispatched once; the duplicate result has `duplicate === true`.
- I03 pending/failed never grants: pending event, failed event, unsigned success and an unmatched reference leave no entitlement and the order not `paid`.
- I04 one verified payment fulfils once: a second successful transaction id for the same order stores a `flagged` event with reason `duplicate_payment` and grants nothing more.

## Also cover (decisions to assert)
- Success happy path: amount and currency equal `orders.total_minor`/`currency` (server order, not payload); order `paid` with `paid_at`; attempt `succeeded`, `active_order_id` null, `signature_valid` true; coupon redeemed via TransitionOrder; learner (not payer) gets the entitlement for a parent-pays-for-child order.
- Failure: signed failure closes the open attempt (`failed`, `failure_code` `declined`, slot freed), outcome `attempt_failed`, order stays `pending` (payer can call `StartCheckout` again, sequence 2); a later signed success for that order (new transaction id) is accepted and pays it. Failure after the attempt already succeeded, or on a paid/cancelled order, is `ignored` and changes nothing.
- Out of order: pending after success is `ignored`; success after the order was cancelled or failed is `flagged` reason `order_closed`, no entitlement; refunded/voided callbacks are `flagged` `refund_or_void_received` (no state change, refunds are T-P8-06); a success arriving after a refunded event for the same transaction id is `flagged` `refunded_before_success`.
- Unmatched: valid signature with unknown reference stores outcome `unmatched`, 200, `payment.flagged` audit, no state change; callback without reference too.
- Order paid by manual proof first, then Paymob success: `flagged` `duplicate_payment`, no second entitlement.
- Order with a non-course line or inactive market (SA): success is `flagged` (`unsupported_lines` / `market_unavailable`), order not paid.
- Gateway mismatch (attempt.gateway differs from the verifying gateway): `flagged` `gateway_mismatch`.
