## What was built
- Settings group `marketing` (`MarketingSettings`: `ga4_measurement_id`, `meta_pixel_id`, both null = off; migration `2026_11_17_500000_seed_marketing_settings`, registered in `config/settings.php`). Config `config/consent.php`: `version` (`cookies-v1-draft`, env `COOKIE_CONSENT_VERSION`), `cookie` (`yg_cookie_consent`), `lifetime_days` 180, `excluded_routes` (route-name patterns), `tag_cookies`, `tag_cookie_prefixes`.
- Domain `App\Domain\Privacy`: `CookieConsent` (value object; cookie value `<version>|accepted` or `<version>|declined`; another version or garbage = not decided), `MarketingTagIds` (GA4 `^G-[A-Z0-9]{4,20}$`, Pixel `^\d{6,20}$`), `Actions\RecordCookieConsent` (signed-in adult: `consents` row type `cookies`, version, `granted_at`; decline or withdraw sets `withdrawn_at` on active rows; accepting the same version twice keeps one active row; guests store nothing in the database), `Queries\MarketingSurface` (true only for layout variant `public`, not `minimal`, not a child account, not parent context, route name set and not in `excluded_routes`), `Queries\ActiveMarketingTags`. `App\Domain\Settings\Actions\SaveMarketingTags` (permission `content.seo.manage`, active user, validates shapes, audit `marketing.tags_saved` with before/after IDs, no audit when unchanged).
- HTTP: `GET /cookies` (`consent.show`, preference page) and `POST /cookies` (`consent.store`, throttle 30/min, field `decision` = `accept|decline`; 403 for a child account or parent context; redirects back to a same-host previous URL, else `consent.show`; JSON request gets 204). It sets the httpOnly SameSite=Lax cookie (encrypted by Laravel) and, on decline, expires `_ga`, `_fbp`, `_fbc` and any `_ga_*` cookie sent by the browser. `App\Http\Consent\ConsentSurface` resolves per request: `active` (surface allowed AND at least one valid ID), `banner` (active, no valid decision, not the `/cookies` page), `tags` (only when active and accepted).
- Layout `components/layouts/base.blade.php` includes `<x-consent.tags>` at the end of `<head>` (GA4 gtag and Meta Pixel inline scripts, IDs through `@js`) and `<x-consent.banner>` after `<main>` (banner `[data-consent-banner]` with buttons `[data-consent=decline]` and `[data-consent=accept]`, plus the persistent link `[data-consent-settings]` to `/cookies`). With no ID configured, or on a non-marketing surface, nothing is rendered at all. A database error while reading settings counts as "off".
- Admin: Filament page `MarketingTags` (admin panel, slug `marketing-tags`, `[data-marketing-tags]`, `edit` action with two fields), gated by `content.seo.manage`.
- Lang `lang/{ar,en}/consent.php`, audit label `marketing.tags_saved`. All wording is a DRAFT placeholder (do not test as final copy).

## Also cover
- Consent record: a signed-in adult accepting gets one `consents` row (`type=cookies`, `version=cookies-v1-draft`, `granted_at` set, `withdrawn_at` null); accepting again adds no row; declining sets `withdrawn_at`; accepting after a version bump (`config(['consent.version' => 'cookies-v2'])`) closes the old row and adds a new one; other users' rows are untouched. Guests create no `consents` row. The cookie is httpOnly, SameSite=Lax, about 180 days, name from config.
- Revocation: with an accepted cookie, `POST /cookies decision=decline` returns a `yg_cookie_consent` cookie ending `declined`, plus expiry cookies for `_ga`, `_fbp`, `_fbc` and, when the request carried `_ga_ABC123`, for that name; the next page has no tags and no banner, and the Cookie settings link is still present. `/cookies` shows `[data-consent-state]` none/accepted/declined correctly; with no IDs configured it shows the "not used" text and no buttons. A plain form post (no JS) works and redirects back; a `Referer` from another host redirects to `/cookies`. A missing or other `decision` fails validation and sets no cookie.
