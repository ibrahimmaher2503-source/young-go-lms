- A2 Pruning removes only expired records per class: for each class create one row older than the cutoff and one newer, set the days through `SaveRetentionPolicies` (or the default), run `PruneRetainedData` (and the command) and assert only the old row of that class is gone and other classes are untouched. Financial tables are never touched: seed old orders, refunds, receipts, certificates, consents and `activity_log` rows with ancient dates, set every class to its minimum and assert they all remain; `ProtectedData::assertNotProtected(['orders'])` throws `LogicException` and no `RetentionClass::tables()` intersects `ProtectedData::TABLES`.

## Also cover
- Request workflow: self request for export/correction/deletion creates a `requested` row and audit; second open request of the same type -> `ValidationException` `privacy.error_already_open`; a different type is allowed; correction without details refused; a parent can file for a verified child (`GuardianChildLink` status verified) but not for an unlinked, pending-link or other child (`AuthorizationException`; the HTTP route answers 404); an anonymized or inactive requester/subject refused; staff roles (admin, instructor) cannot request deletion (`privacy.error_staff_account`) and `AnonymizeAccount` refuses them even if a request row exists. Approve: needs `privacy.manage` (support, finance, student, inactive admin -> `AuthorizationException`), idempotent when already approved, refuses completed/rejected. Reject: reason under 10 chars refused, from requested or approved, `review_note` stored and visible to the requester on the page. Complete: refuses `requested` status; correction without note refused; completed twice is a no-op with a single audit event. Cancel only by the requester while `requested`.
- Export archive: open the zip (`ZipArchive` on the stored file): contains `manifest.json`, `README.txt`, and a JSON file per topic including `profile`, `orders`, `ai_conversations`, `ai_messages`, `help_requests`, `submission_files` with the learner's own uploaded file under `submission_files/`; content belongs only to the subject (seed a second learner with distinct data and assert none of it appears); excluded: `password`, `remember_token`, `two_factor_*`, `token` of certificates, payout details, `id_document_*`, quiz `snapshot` (answer key), `ai_safeguarding_flags`, `payment_events`; stored under `privacy/exports/<uuid>.zip` on the private disk (not `public`); `archive_sha256` equals the file hash; `archive_expires_at` = now + DataExports days.
- Download: requester gets the zip with `no-store`; another logged-in user, the subject if not the requester (a parent requested), a guest, an expired archive, a non-export type or an uncompleted request all get 404 (guest redirects to login); download records `archive_downloaded_at` and audit `privacy.export_downloaded`.
