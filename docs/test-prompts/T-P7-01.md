## What was built
- Config `config/ai.php`: `teen_age` (OPEN, null), `max_words_en` (70), `max_sentences` (4), `question_max_chars` (300), `max_output_tokens` (220) and the `ai.assistant.*` block (`timeout_seconds` 15, `retries` 1, `follow_up_turns` 3, `history_pairs` 2, `retrieval_top_k` 6, `trim_tolerance` 1.25, `quote_max_words` 25, `quote_min_chars` 8, `quote_min_similarity` 88, `leak_ngram_words` 6). No migration: tables come from T-P3-10.
- Models `AiConversation`, `AiMessage`, `AiUsage` (`ai_usage`, only `student_hash`, never the id).
- `App\Domain\AI\Actions\AskLessonAssistant` `__invoke(User $learner, Lesson $lesson, AssistantQuestion $input): AssistantReply`. Order: learner active + `ai.ask` permission (else `AuthorizationException`); `AssistantEligibility::check` (else `AssistantRefused` with the `UnavailableReason`); document = `$lesson->activeCurriculumDocument()` (never from the client); thread (conversation must belong to the learner AND this lesson, else `ValidationException` on `conversation_id`; a thread on an older document version starts a new thread); question 1..300 chars (else `ValidationException` on `question`); follow-up cap; `ContextBuilder`; entitlement flush + eligibility + active-document re-check; prompt from `AiPromptVersion::current()` via `PromptRenderer` (max words per reply language); `provider->complete()` with `timeoutSeconds` 15; `OutputGuard`; one retry on guard rejection; persist (2 `ai_messages`, 1 `ai_usage`, audit `ai.assistant_asked`) in one transaction. An audit that cannot be written rolls everything back.
- `AssistantOutcome` stored in `ai_messages.status`: `answered`, `not_in_source`, `out_of_scope`, `fallback`. Only `answered` stores content and `source_pages`, `quote_verified = true`. The fixed learner text for the other states is `ai.not_in_source`, `ai.out_of_scope`, `ai.temporarily_unavailable` (reply `message`).
- `OutputGuard`: JSON only (no markdown fences). `not_in_source` / `out_of_scope` need just `status` (model text is discarded). `answered` needs exactly the keys `status, answer, source_pages, support_quote, language` (`language` ar|en, pages are ints). Failures: `schema`, `citation` (cited page not in this version), `length`, `leakage`, `quote`. Length: up to 4 sentences and 80 (ar) / 70 (en) words; an answer up to 25 percent over the word cap, or with more than 4 sentences, is trimmed at the last full sentence (`guard_flags.trimmed`), above that it is rejected and retried. Quote: at most 25 words, at least 8 normalised characters, found verbatim after Arabic normalisation (alef variants, ya, ta marbuta, diacritics, tatweel, digits, punctuation) or fuzzy (about 88 percent) on one of the cited pages. Leakage: `lesson_source`, `[[page`, `lesson id N`, `ai_messages` etc., a URL not in the lesson text, or 6 consecutive words copied from the system rules.
- After the retry: quote failure becomes `not_in_source`; any other guard failure becomes `fallback`; a provider exception or `latencyMs` above 15 s becomes `fallback` at once (no retry). `ai_usage.result` is `answered`, `not_in_source`, `out_of_scope`, or the reason (`provider_error`, `timeout`, `schema`, `citation`, `length`, `leakage`). Tokens are summed over both attempts.
- Context: approved page text only (`approved_text`, never `raw_text`) of the active READY version. At or below `ai.full_context_max_tokens` (chars / 4) all pages go in, page-tagged `[[page N]]`; above it only the pages of the top 6 chunks (keyword + embedding score; falls back to one chunk per page if the document has no chunks). Verification always uses all approved pages of the version.
- Thread rules: history is the last 2 answered Q/A pairs (answers only). First question plus 3 follow-ups; the 5th is refused (`AssistantRefused::THREAD_LIMIT`, `ai.thread_limit`). `mode = simpler` re-explains the last question of the thread (needs an answered last message, once per question, `AssistantRefused::SIMPLER_LIMIT`, does not count as a follow-up); without a valid conversation it is a 422.
- HTTP `AssistantController` (`routes/assistant.php`, session auth + active account + 2FA): `GET /api/v1/lessons/{lesson}/assistant` returns `available`, `reason`, `message`, `key_terms` (approved, max 5). `POST /api/v1/lessons/{lesson}/assistant/messages` body `question` (required unless `mode=simpler`), `video_position`, `conversation_id`, `mode` (normal|simpler); other body fields (e.g. `lesson_id`) are ignored. Answered: `text/event-stream` with `event: token` chunks of the validated answer then `event: result` (`state, message, message_id, conversation_id, source_pages, language, quote_verified`). Others JSON: 403 not eligible, 409 no READY document / not a recorded lesson, 422 validation, 429 quota (`reset_at`), 503 `fallback`; not_in_source and out_of_scope are 200 JSON. Response never contains source text or the quote. `Cache-Control: private, no-store`.
- Lang: `ai.thread_limit`, `ai.simpler_limit`, `ai.invalid_conversation`, `ai.question_invalid`; audit label `ai.assistant_asked` (AR and EN).

## Acceptance
- A1 An answer with a verified quote is shown; an unverified quote never is. Seed a lesson (type video, `ai_enabled`, active READY document with 2 approved pages), a consented student with the `student` role, flags `ai.assistant` and `ai.minors` on, and bind `LessonAccessChecker` to a stub that allows (as `tests/Feature/AI/AssistantEligibilityTest.php` does). Queue a valid answered JSON citing page 1 with a quote that is on page 1: reply `answered`, message text equals the answer, `source_pages` `[1]`, `ai_messages` row `quote_verified` true. Then a quote that is not on the cited page queued twice: exactly 2 provider requests, status `not_in_source`, the answer text is nowhere in the response, the `ai_messages.content` is empty. Also: a quote that is on the other page only, a quote with different diacritics/alef forms of a real phrase (accepted), a quote of 26 words, a quote under 8 characters, missing `support_quote`, extra key, non-JSON, markdown-fenced JSON, page that does not exist, `source_pages` as strings (each rejected, retried once, then fallback or not_in_source as above). First answer bad and second valid: one answered reply, 2 requests, `guard_flags.attempts` 2, usage tokens summed.
- A2 Another lesson's text never reaches the provider. Create a second lesson with its own READY document containing a unique marker. Ask on lesson 1 via the endpoint with body `lesson_id` = lesson 2, `document_id`, `course_id`, `student_id` of someone else: assert every `requests()` entry's `cacheablePrefix` and `turns` contain the lesson 1 text and not the marker, and `ai_conversations.lesson_id` is lesson 1 and `student_id` the session user. A `conversation_id` of another student's or another lesson's thread is a 422 and sends no provider request. Chunked mode (set `ai.full_context_max_tokens` to a tiny value, add `lesson_document_chunks` for the document and one for lesson 2): only pages of this document appear, tagged `[[page N]]`, and `raw_text` of a page whose `approved_text` is null never appears. A student without entitlement (stub returns false) or with the flag off gets 403 and no provider request; a document that is deactivated between the first check and prompt construction (use a closure answer is not possible: swap the stub to deny after the first `check` call, or delete the active flag in a `Closure` bound checker counter) gets 409/403 and no provider request. Lesson without READY document: 409.
- A3 Provider timeout or error returns the fallback state and the lesson is unaffected. `failNext(new RuntimeException)`: endpoint 503 `state` `fallback`, message `__('ai.temporarily_unavailable')`, exactly 1 provider request (no retry), `ai_messages` status `fallback`, `ai_usage.result` `provider_error`, exception reported. A closure answer cannot set latency, so for the timeout bind a decorator provider whose `complete()` returns an `AiCompletionResult` with `latencyMs` 16000: status `fallback`, `ai_usage.result` `timeout`, 1 request. `NullAiProvider` bound (O-014): fallback, nothing thrown to the client. Progress, lesson page and PDF routes still return 200 afterwards. Audit failure (mock `AuditLogger::record` to return null): 503 fallback and no `ai_messages` / `ai_usage` rows.
- A4 Over-length answers are trimmed or retried per spec. English answer of 3 sentences and 80 words (cap 70, within 25 percent): accepted, trimmed to whole sentences, `guard_flags.trimmed` true, final sentence not cut mid-way. Arabic answer of 79 words accepted untouched; 90 words in Arabic is trimmed. 5 short sentences: trimmed to 4. 100 words: rejected, retried, if the retry is valid it is shown, if it is also long then `fallback` (2 requests). A single sentence longer than the cap but within 25 percent: no sentence fits, so retried.

## Also cover
- Output guard leakage: answer containing `lesson_source`, `[[page 1]]`, `lesson id 5`, a URL not in the lesson (rejected) and a URL that is in the lesson text (accepted); a 6-word run copied from the system rules (rejected; read the rules from the request prefix before `<lesson_source`).
- `not_in_source` and `out_of_scope` replies show the fixed lang text, never model text, 200 JSON with `quote_verified` false and empty `source_pages`. The default `FakeAiProvider` answer (`DEFAULT_ANSWER`) yields `not_in_source`.
- Request contents: `promptVersion` equals the active `ai_prompt_versions.version`, `maxTokens` 220, `timeoutSeconds` 15, `responseSchema` has the 5 properties, `userHash` is 64 hex chars and does not contain the student id or email, same student same hash, different students different hashes; the prompt contains the style tier text for the learner (no birth date: kids when unknown or `ai.teen_age` null; adults when `ai.adult_age` set and reached; teens with `ai.teen_age`), the max words value 80 for an Arabic question and 70 for English, and the reply language (Arabic script question = Arabic; Latin question with locale ar = the Franco-Arabic wording).
- History: second turn in a thread sends the first Q and its answer (not its quote), at most the last 2 pairs; fallback and not_in_source turns are not sent as history; a new document version starts a new thread (new `ai_conversations` row, no old turns); 4th follow-up allowed, 5th question refused with `ai.thread_limit` and no provider request; `simpler` once per question (second is `ai.simpler_limit`), does not count as a follow-up, reuses the last question text, adds the simpler instruction to the last turn.
- Validation: empty, whitespace-only, 301-character question (422, no provider request, no rows); a 300-character Arabic question is accepted (character count, not bytes); `video_position` negative 422. Parent acting as a child (`ActingLearner`) is the child for eligibility; the audit row carries `acting_for`.
- Persistence: assistant row stores `prompt_version`, `model` (`fake-model`), `cache_hit` false; no `ai_messages` or `ai_usage` column contains lesson text or the support quote; `ai_usage` has no student id; audit `ai.assistant_asked` (actor learner, after has lesson_id, document_version, status, prompt_version, quote_verified, attempts, no question text) and both AR and EN labels exist.
- GET status: available with up to 5 approved key terms only (unapproved hidden); each unavailable reason returns its `reason` and localized `message`; no source text.
- Arch/regression: `tests/Arch`, `app:check-translations`, `app:check-rtl`, and the T-P3-09 and T-P3-10 groups stay green (`PromptRenderer::render` gained an optional last `$maxWords` argument; existing calls are unchanged).
- Known gaps (T-P7-02+): no input guard (PII masking, moderation, injection heuristics), quiz guard, answer cache, quotas or budgets (eligibility only reads existing counters; nothing increments them), no UI, no feedback or help request, no circuit breaker or fallback provider, no eval harness. The question is stored unmasked in `ai_messages.content` until PII masking lands. The provider is called with `complete()` and the validated answer is streamed to the client afterwards, so nothing unverified is ever sent.
