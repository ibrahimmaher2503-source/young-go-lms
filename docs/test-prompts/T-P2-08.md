## Acceptance
- A1 Rate limit and honeypot block spam: (a) POST `/contact` with a filled `website` returns 204 and creates no row and no audit entry; same for POST `/newsletter`. (b) With valid data, the 4th POST within a minute from the same `REMOTE_ADDR` returns 429 (set `contact.rate_limit.per_minute` via config to keep it small); a different address is not limited; the hourly cap applies too; contact and newsletter buckets are independent. (c) Validation: missing name/email/message, bad email, message under 10 or over 3000 chars, name over 120, invalid phone (`123`) -> 422 with field keys; valid Egyptian phone `01012345678` is stored as `+201012345678`; empty phone is stored as null. (d) Newsletter without `consent` -> 422 `consent` and no row.
- A2 Unsubscribe works without a login: a subscriber made through the form, `GET $subscriber->unsubscribeUrl()` as a guest returns 200 showing `[data-unsubscribed]`, sets `unsubscribed_at`, repeating the link is still 200 and does not move the timestamp. An unsigned URL, a URL with a changed id or a tampered signature returns 403 and the subscriber stays subscribed. A signed link for a missing id returns 404. The link is throttled (21st call in a minute returns 429).
