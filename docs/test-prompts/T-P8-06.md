- Approve: requested -> approved (repeat no-op, other states `not_requested`), audit `refund.approved`. Reject: requested or approved -> rejected with reason 10..1000 (repeat no-op, executed/failed/processing refused `not_rejectable`), audit `refund.rejected`; frees the balance.
- Execute: needs `payment.refund`; also `manual_entitlement.grant` only when access will be revoked (`AuthorizationException` before anything moves). Approved only (`not_approved`); order must still be paid/partially_refunded. Gateway method: needs a configured gateway with `supportsRefunds()` and the same `key()` as the stored gateway, else `gateway_unavailable` (nothing changes, refund stays approved); sets `processing`, calls the gateway outside the transaction, on `PaymentGatewayException` marks the refund `failed` (+ `failure_code`, audit `refund.failed`) and throws `gateway_failed` with nothing else changed (no manual fallback). Manual method: needs `external_reference` 3..64 (`external_reference_invalid`). Success: refund `executed`, order -> `partially_refunded` or `refunded` through `TransitionOrder` (audit `order.status_changed`), revoke per policy, refund receipt (credit note) issued, audit `refund.executed`. Repeat execute is a no-op.
- Revocation: only entitlements with `source_ref = 'order:<reference>'` and source purchase or manual_payment are revoked (reason `refund <ref>`); another grant of the same course (e.g. manual_grant) stays.
