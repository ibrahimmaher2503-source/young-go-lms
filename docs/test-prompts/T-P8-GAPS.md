## Acceptance
- A1 Refund of a plan order: pay a plan order (T-P8-08 helpers), then request, approve and execute a **full** refund as finance/admin. Expect: entitlements with source `subscription` and that period's ref are revoked (access denied via `EntitlementService`), the `subscription_periods` row ends now, subscription `status=expired`, audit `subscription.refunded` plus `refund.executed` with the revoked count, order `refunded`. `SendSubscriptionRenewalReminders` sends nothing for it. A later renewal order for the same plan and learner can be created and paid and reactivates it. Partial refund under `full`: nothing revoked, period and subscription untouched; under `any`: revoked; under `none`: never. A renewal period bought early (two periods) refunded for the later one: only that period's entitlements are revoked, the subscription stays `active`. Executing again is a no-op (no second audit). A refund without `manual_entitlement.grant` stays refused before money moves.
- A2 Refund of a bundle order revokes the bundle-sourced entitlements (`order:<ref>`), keeps other sources (a separate course purchase, subscription, free) and does not touch courses the allocation skipped as already owned. A mixed order (course + bundle + plan) revokes all three on a full refund.
- A3 Plan checkout entry: a signed-in learner opens `/checkout/plan/{id}`, picks the learner (a parent with a child works), continues to `checkout.order` with one plan line at the plan price; inactive plan, plan without EG price or without a published course = 404 and `start` is refused; a learner covered beyond the renewal window is disabled and `start` returns the `commerce.already_subscribed` error; a second start returns the same pending order. Paying (manual approval or Fake webhook) starts the period.
- A4 Public pages: `/en/plans` and `/ar/plans` render names, term, price, included published courses, hreflang/canonical, `dir=rtl` in AR; 404 with no sellable plan; CTA is sign-in for guests and checkout for signed-in users. `/en/bundles/{id}` and `/en/bundles/{id}-slug` render courses, price, CTA; wrong id, inactive or unpriced bundle, bundle with a draft course = 404. `/sitemap.xml` includes both when sellable and neither otherwise.
- A5 `/my/subscription`: a guest is redirected to login; it shows plan, period start/end, grace end, state badge (active, grace, cancelled, expired) in AR and EN; a payer (parent) sees the child's subscription, another account's subscription is absent and renew/cancel on it is 404. Renew inside the window creates one pending plan order (a second click returns the same order) and redirects to `checkout.order`; before the window the button is absent and a forged POST gives the `commerce.already_subscribed` error bag. Cancel sets `cancelled_at`, keeps access to period end, flashes `subscriptions.my_cancel_done`, audit `subscription.cancelled`, the button disappears; cancelling twice is a no-op.
