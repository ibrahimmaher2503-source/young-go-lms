## Rule semantics (working defaults, O-020 stays open)
- Auto completion needs at least one rule on and every rule that is on met. No rule on: never completes by itself.
- `manual_approval` on: the evaluator only measures; the row is created by `ApproveCourseCompletion` (source manual). Approval is allowed whatever the rules say (override), once per learner.
- Lessons: required, published, not archived lessons (the set `RecalculateCourseProgress` uses); met when `completed_required * 100 >= lesson_percent * total_required` and total > 0.
- Quizzes: every required published quiz item has a submitted attempt with `passed = true`, or (quiz without a pass mark) a reviewed attempt (`needs_review` false). Zero required quizzes = not met.
- Assignments: every required published assignment has a submission with status `accepted`, or `graded` while `config('learning.completion.graded_counts_as_accepted')` is true. `rejected`, `returned`, `submitted`, `resubmitted`, `draft` never count. Zero required = not met.
- Attendance: completed, non-archived sessions of the course that have no cohort or whose cohort seats the learner. `present` and `late` attend, `excused` leaves the denominator, a missing mark counts as absent. Met when `attended * 100 >= attendance_percent * counted` and counted > 0 (no finished session = not met).
- Completion is never removed by a later rule or data change. Evaluating again returns the existing row and dispatches nothing.
- Authorization: saving rules and approving need `Gate::allows('update', $course)` (admin, or instructor with manage scope). Others get `AuthorizationException` (page: 403). Approval also needs the person to have (had) access (`CourseLearners`) and a reason of 3 to 500 characters.
- Audit: `course.completed` (actor null, after `{learner_id, source}`), `course.completion_approved` (actor, after `{learner_id, source, reason, rules_met}`), `course.completion_rules_saved` (before/after rule values). An audit that cannot be written rolls the write back.

## Acceptance
- A1 Each rule combination is evaluated correctly (dataset test). One helper seeds a course with 2 required lessons, 1 required quiz (pass mark 50), 1 required assignment and 2 completed live sessions; each dataset row states what the learner did and the saved rules, then asserts the `CourseCompletionEvaluator` result. Rows:
  - no saved rules (defaults): both lessons done = completed; one lesson = not.
  - lessons 50: one of two done = completed; none = not. Lessons 100: one of two = not.
  - quizzes only: passed attempt = completed; failed or `needs_review` = not; no attempt = not; quiz without a pass mark and a reviewed attempt = completed.
  - assignments only: `accepted` = completed; `graded` = completed (default) and not when the config flag is false; `rejected`, `returned`, `submitted` = not; graded and then re-decided as rejected = not.
  - attendance 80: 2 of 2 present = completed; present + late = completed; 1 of 2 = not; present + excused (1 of 1 counted) = completed; both excused = not; one unmarked = absent; a cohort session where the learner has no seat is ignored; a session not completed (open or scheduled) is ignored; zero sessions = not.
  - lessons + quizzes: both met = completed; either missing = not.
  - all four rules: all met = completed; each one missing in turn = not (four rows).
  - `manual_approval` with everything met: the evaluator returns null and creates no row; `ApproveCourseCompletion` then creates a manual row.
  - no rule on (everything off): nothing completes even with everything done; manual approval still works.
  - a rule on with nothing to measure (quizzes on, no required quiz; archived or draft required items do not count) = not completed.
- A2 Duplicate events do not duplicate completion: fire `CourseCompletionInputChanged` (or call `CompletionTrigger::changed`) three times and run the evaluator directly twice; assert exactly one `course_completions` row, one `course.completed` audit and one `CourseCompleted` dispatch (`Event::fake`). For the race, pre-create the row and assert the evaluator returns it without a new event. A manual approval on an existing completion fails with `completion.already_completed`.
