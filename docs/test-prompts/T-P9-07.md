## What was built
- No migration, no new permission. `config/reports.php` gains `dashboard_cache_seconds` (env `DASHBOARD_CACHE_SECONDS`, default 60, 0 = off) and `dashboard_days` (30).
- `App\Domain\Reports\Dashboards`: `RoleDashboard::for(User $user, string $panel): DashboardData` (`panel` = `admin`, `finance`, anything else = instructor view), `DashboardData` (`kpis`, `queues`, `days`, `isEmpty()`), `DashboardKpi` (`key`, `kind` count|percent|money, `value`, `money` = currency => minor units, `secondary`, `icon`, `tone`, `isEmpty()`), `DashboardMoney::format($minor, $currency)` (PriceFormatter, locale aware; an unknown currency falls back to `1,234.50 XYZ`).
- `App\Domain\Entitlements\EnrollmentReport::activeLearners(?array $courseIds): int` (distinct learners with access now; null = all courses, empty list = 0).
- UI: `WorkspaceDashboard::content()` adds the view `filament.staff.dashboard-kpis` (root `[data-role-dashboard]`; KPI tile `[data-kpi=<key>]` with `[data-kpi-value]` = raw value (money: JSON of currency => minor units) and `[data-kpi-empty]` when there is nothing in the period; queue row `[data-queue=<key>]` with `data-queue-count`, `[data-queue-empty]` when zero; empty state text `dashboard.empty_title`). The existing summary strip and quick links are unchanged. Lang `lang/ar|en/dashboard.php`.
- Everything is permission gated; nothing leaks across roles. KPIs come from the T-P9-06 report definitions through `ReportCatalog::scope()` (last 30 days, Egypt-day boundaries); queues are live counts, never cached.

## KPI and queue matrix (keys)
- Admin panel, super admin/admin: KPIs `revenue` (money, Sales `net`), `orders` (Sales `orders` total), `refunds` (money, Refunds `refund_amount`, secondary = refund count), `active_learners`, `completions` (Enrollments `new_completions`), `ai_requests` (secondary = errors), `ai_cost` (needs `report.view` and `ai.view_usage`). Queues `manual_payments` (secondary overdue), `refunds_requested`, `instructor_applications` (status pending), `reviews_pending` (course reviews pending), `help_awaiting` (new + in_progress, secondary overdue by `due_at`).
- Finance panel: KPIs `revenue`, `orders`, `refunds`, `instructor_balances` (ledger entries accrued + pending + approved, per currency), `instructor_held` (held). Queues `manual_payments`, `payment_mismatches` (open), `refunds_requested`, `settlements_pending` (settlements draft or approved: money = total per currency, secondary = batches). No AI, learner or enrollment KPIs.
- Instructor panel (`instructor_academy`/`instructor_independent`): KPIs `my_learners` (distinct active learners in assigned courses), `completions`, `completion_rate` (all completions / all enrolled learners over own courses), `earnings` (money, own ledger net, InstructorEarnings `net`). Queues `submissions_awaiting` (secondary overdue), `essays_awaiting`, `help_awaiting` (only requests assigned to them). Never sales, refunds, AI or finance queues.
- A user with no permission (e.g. `student`, suspended staff): empty `DashboardData`; `support` has only the `help_awaiting` queue.

## Acceptance
- A1 KPI values equal the report queries: seed paid orders in EGP and SAR, executed and non-executed refunds, enrollments, completions, AI usage rows. For an admin each KPI equals the matching totals of `SalesReport`, `RefundsReport`, `EnrollmentsReport`, `AiUsageReport` run through `ReportCatalog::scope()` with the same 30-day range (`revenue`/`refunds` money per currency, `orders`, `completions`, `ai_requests`, `ai_cost`); finance `revenue` equals the Sales `net` totals; `instructor_balances` equals the ledger sum of non-held, non-paid entries; `manual_payments`, `refunds_requested`, `payment_mismatches` equal `ManualPaymentQueue::summary()['pending']`, `RefundQueue::summary()['requested']`, `ReconciliationReport::openCount()`.
- A2 Instructor sees own courses only: two instructors with different courses (`course_instructors`), learners and completions in both, ledger entries for both, help requests assigned to each. Instructor A's `my_learners`, `completions`, `completion_rate`, `earnings` count only course A / own ledger; `help_awaiting` only requests assigned to A; submissions and essays only from courses A may review; admin sees both.
- Also: money is per currency (EGP and SAR tiles show two separate formatted values, never summed; Arabic locale uses the symbol, English the code, numbers in Latin digits); empty states (new database: tiles render `data-kpi-empty`, queues `data-queue-empty`, no exception); pages render for `ar` and `en` and the AR page is RTL; caching (`dashboard_cache_seconds` 60): a second call returns the first values after data changes, a different user or panel does not share the entry, queues change immediately, and 0 disables the cache; suspended staff get nothing; Arch and `tests/Feature/Invariants` still pass (I01: the entitlements table is only read inside `Entitlements\EnrollmentReport`).
