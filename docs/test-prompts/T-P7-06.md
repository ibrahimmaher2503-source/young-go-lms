## What was built
- **Resilience** `app/Domain/AI/Resilience/`:
  - `ResilientProvider` wraps the container provider for `AssistantEngine` only (contextual binding in `AppServiceProvider`). `app(AiProviderInterface::class)` itself is still the plain `FakeAiProvider` (local/testing) or `NullAiProvider`, so existing tests and `RecordingProvider` are unaffected. Routes: primary (`ProviderRegistry::activeKey()`) then optional fallback (`fallbackKey()`, built with `ProviderRegistry::make`). A route is skipped while its circuit is open. A thrown error (not `AiProviderNotConfigured`) counts as a failure; `AiProviderNotConfigured` is rethrown without counting; a result with `latencyMs > timeoutSeconds * 1000` counts as a failure but is still returned when no other route answers (so the pipeline still reports `timeout`). No route able to answer: the last exception is thrown, or `AiProviderCircuitOpen` when every circuit is open. `AssistantEngine` does not `report()` `AiProviderCircuitOpen` (nor `AiProviderNotConfigured`).
  - `CircuitBreaker` (shared cache, keys `ai:breaker:<route>:failures|open_until|opened_at|trial`): `recordFailure` increments a counter with the window TTL (`AiSettings::breaker_window_seconds`, default 120); at `breaker_failures` (default 5) the route opens for `breaker_cool_off_seconds` (default 60) and the counter is cleared; `recordSuccess` clears everything; after the cool-off `allows()` lets exactly one trial through (`Cache::add` lock) and a failed trial re-opens at once; `state()` returns `CircuitState` (closed, open, half_open, failures, retryAt, openedAt); `reset()` closes it.
  - `ProviderRegistry`: keys `unconfigured` and, only in local/testing, `fake`. Operator choice (`AiSettings::provider`) wins when it is a known key, else config/environment as before (fake in local/testing or `AI_PROVIDER=fake`, otherwise unconfigured). `fallbackKey()` is null when unset, unknown or equal to the primary. `AskLessonAssistant` now writes `ai_usage.provider` from `ProviderRegistry::currentKey()` instead of `config('ai.provider')`.
- **Settings**: `AiSettings` gained `provider`, `model`, `fallback_provider` (nullable), `breaker_failures` 5, `breaker_window_seconds` 120, `breaker_cool_off_seconds` 60, `message_retention_days` 180, `usage_retention_months` 24 (migration `2026_11_17_400000_add_ai_admin_settings`). The `model` value is stored for the future adapter; nothing reads it yet.
- **Actions** `app/Domain/AI/Admin/Actions/` (all final, `__invoke`, each audits through `AuditLogger` inside the transaction and throws `RuntimeException` when the audit returns null; subject is the actor, course or curriculum item):
  - `EnableAssistantGlobally($actor, $approvalReference)`: needs `ai.configure`; empty or over 255 chars -> `ValidationException` (`approval_reference`); delegates to `EnableGatedFlag` (Gate `enable-gated-platform-flag`; `Gate::before` lets `super_admin` pass, others are denied unless the test defines the gate) which stores `flag_approvals` and activates `ai.assistant`; audit `ai.global_enabled` with the reference in context. `DisableAssistantGlobally($actor)`: needs `ai.configure`, deactivates the flag, audit `ai.global_disabled`.
  - `SetCourseAssistant($actor, $course, bool)` (audit `ai.course_switched`, no row and no audit when unchanged) and `SetLessonAssistant($actor, $curriculumItem, bool)` (audit `ai.lesson_switched`; non-lesson item -> `ValidationException`). Both authorize with `TestConsoleAccess::allows` (active, `lesson_document.upload`, policy `update` on the course): admin and the manage-scope instructor of that course only.
  - `SaveAssistantQuotas($actor, array)`: `questions_per_student_day` 1-1000, `questions_per_student_lesson_day` 1-1000 and `lte` the day value, `monthly_budget_minor` and `course_monthly_budget_minor` nullable 0-1e9, `budget_currency` 3 letters required with either budget (stored upper case), `budget_alert_percent` 1-100. Audit `ai.quotas_saved` with before/after. The values are the ones `QuotaLedger`, `AssistantEligibility` and `BudgetGate` already read.
  - `SaveAssistantProvider($actor, array)`: `provider` required and in `ProviderRegistry::keys()`, `fallback_provider` nullable, in keys and different from provider, `model` nullable max 80, `prompt_version` must exist and becomes the only active `ai_prompt_versions` row, breaker values `breaker_failures` 1-100, `breaker_window_seconds` 10-3600, `breaker_cool_off_seconds` 5-3600. Audit `ai.provider_saved`.

  - `PruneAiData` (command `ai:prune`, scheduled daily 03:30): deletes `ai_messages` older than `message_retention_days` except messages a `help_requests.ai_message_id` points at (their `ai_feedback` rows go with deleted messages), conversations with no messages left that are older than the cutoff and not referenced by `ai_safeguarding_flags` or `help_requests`, `ai_usage` older than `usage_retention_months`, expired `ai_answer_cache`, `ai_quota_counters` older than 7 days. ## Acceptance
- A1 N consecutive failures open the circuit and route to the fallback or the outage state. With `AiSettings::breaker_failures = 3`: three asks through `AskLessonAssistant` with `failNext(new RuntimeException)` each end `fallback` / `ai_usage.result = provider_error` with the provider called each time; `CircuitBreaker::state('fake')->state` is `open` after the third; the fourth ask ends `fallback` with **zero** new provider requests (`$fake->requests()` count unchanged), no exception reported (`Exceptions::fake()` / `report` spy sees none for `AiProviderCircuitOpen`), quota refunded (counters unchanged), the lesson page and PDF routes still 200. A success resets the counter (two failures, one success, two failures: still closed). Failures outside the window do not add up (`travelTo` past `breaker_window_seconds`). After `breaker_cool_off_seconds` exactly one trial request is sent: a success closes the circuit, a failure re-opens it at once (no need for N more failures); two concurrent callers during half-open: only one gets `allows() === true`. Fallback (`ProviderRegistry` is final, do not mock it): save settings `provider=unconfigured`, `fallback_provider=fake` through `SaveAssistantProvider`, then build `new ResilientProvider($stubPrimary, app(ProviderRegistry::class), app(CircuitBreaker::class))` where the stub primary (anonymous class implementing `AiProviderInterface`) throws `RuntimeException`; the fallback route is a fresh `FakeAiProvider` made by the registry, which answers `FakeAiProvider::DEFAULT_ANSWER`. After the primary circuit opens, requests go to the fallback and succeed, the learner gets a normal answer, and when both circuits are open `complete()` throws `AiProviderCircuitOpen`. `AiProviderNotConfigured` from the primary is never counted (no circuit opens with `NullAiProvider` bound). A slow result (`latencyMs` 16000) counts as a failure and is still returned when it is the only route (ask ends `fallback`, `ai_usage.result = timeout`). `ResetProviderCircuit` as super admin closes it (state closed, next ask calls the provider, audit `ai.circuit_reset`); an admin gets `AuthorizationException`; unknown route -> `ValidationException`. `ProviderHealthReport` shows primary route, circuit `open`/`closed`, `healthy` false while open, 24 h request/error counts, and a fallback row only when set. Existing behaviour unchanged: `app(AiProviderInterface::class)` is still a `FakeAiProvider` in tests and the T-P7-01..05 groups pass.
- A2 Reports contain no message bodies. Seed conversations whose user and assistant text contains a unique marker string (for example `ZZ-SECRET-QUESTION`), plus `ai_usage` rows of every result (`answered`, `not_in_source`, `out_of_scope`, `cache_hit`, each `GuardKind`, `provider_error`, `timeout`, `schema`, `citation`, `length`, `leakage`). `json_encode(UsageReport::for(...))` and the rendered `AssistantUsageReport` HTML (Livewire test as an admin with `ai.view_usage`) must not contain the marker, a student id, the student hash, a user email or any `ai_messages` content; assert the report queries only `ai_usage` (enable `DB::listen` and check no query touches `ai_messages`, `ai_conversations` or `users`). Numbers: totals for requests, answered, not_in_source, cache_hits, guard_blocks (moderation, safeguarding, injection, quiz_guard), errors (everything else), `error_rate` rounded to 1 decimal, summed tokens and cost, average and p95 latency over rows with `latency_ms > 0` only, `by_day` grouped by date with error counts, `by_model`, `by_lesson` (top 10 by cost, names via the lesson and course title). Date range: rows outside `[from 00:00, to 23:59:59]` excluded; reversed range swaps; an invalid date string falls back to the last 30 days; the page caps a range at 366 days. Empty period shows `[data-usage-empty]`. Console traffic: ask through `AskInTestConsole` and assert the report totals do not change. Insights anonymity: `LessonInsights` for a lesson with asked questions returns `questions` (user turns not in simpler mode), `answered`, `not_in_source`, `out_of_scope`, `fallback`, `not_understood` (`ai_feedback` type `not_understood`), `simpler` (user rows with `guard_flags.mode = simpler`), `topics` (the lesson's approved key terms found, by normalized text, only count > 0, top 10), `pages` (cited pages from answered rows, top 10), `gaps` (the question that precedes each `not_in_source` answer in its thread, grouped by normalized wording, count desc, max 20, 140 chars). The result never contains a student id, email, name, timestamp, conversation id, assistant answer text or a question whose `guard_flags.pii` is non-empty or whose text is empty; questions from other lessons or outside the range are absent. Authorization: usage page 403 for `support`, `finance`, instructor, student, and for a suspended admin; 200 for `admin` and `super_admin`. Insights page: an instructor only lists and reads lessons of courses they manage with `lesson_document.upload` (another course's lesson id set on the component yields no data, not an error leak); admin sees all.
