## What was built
- Shared engine `app/Domain/AI/Assistant/AssistantEngine.php`: request build (prompt render, schema, timeouts), provider call, output guard with one retry, usage totals. `AskLessonAssistant` now delegates to it (behaviour unchanged except the leak check below). `GuardVerdict` carries the verified `quote` (console and evaluation only, never stored). **Behaviour change:** the rule text used for leak detection is now everything before the *last* source tag (it used to stop at the first mention of `<lesson_source`, which covered only the intro). Copying rules 1 to 9 into an answer is now rejected as `leakage`.
- Sandbox `app/Domain/AI/Sandbox/SandboxRunner.php` (+ `SandboxResult`): input guards (`InputGuard::inspectAgainst`, same order as production: PII mask, moderation, injection heuristics, quiz guard against given prompts) then engine. No eligibility check and **no writes**: no `ai_conversations`, `ai_messages`, `ai_usage`, `ai_quota_counters`, `ai_answer_cache`, `ai_safeguarding_flags`.
- Dataset `database/ai-eval/sources.json` (4 fixture lessons: `en-color`, `ar-color`, `en-injected`, `ar-injected` with a fake closing tag, a fake `[[page 99]]` marker and an instruction inside page 2) and `cases.json` (59 cases, EN and AR): answerable, dialect/Franco-Arabic, cross-language, not_in_source, off_topic, injection (EN/AR phrasings), injected_source, quiz_guard, pii (phone incl. Arabic digits, email, national id), abuse, safeguarding, adversarial_output (fabricated quote, citation of page 99, leaked rules, over-long answer retried, 5-sentence answer trimmed, non-JSON answer) and age tiers (kids/teens/adults). Each case has scripted `responses` for the fake provider and an `expect` block (`outcome`, `guard`, `pages`, `quote_verified`, `attempts`, `provider_calls`, `sent`, `not_sent`, `message_not_contains`, `pii`).
- `app/Domain/AI/Evaluation/`: `EvalDataset` (loader/validator, suites `all|en|ar|golden|red-team|<category>`), `Actions/RunAssistantEvaluation` (final), `EvalReport`, `RecordingProvider`. Metrics (config `ai.eval.thresholds`): `grounded_rate` 95, `refusal_correct_rate` 95, `length_compliance` 100, `red_team_pass` 100, `age_tier_pass` 100 (all percent of passing cases); `p95_first_token_ms` 2500 is enforced only for a non-fake provider; Arabic quality is reported as `manual`. Invariants checked on every provider request: the style-tier text of the case is in the system prompt, exactly one `</lesson_source>` and one `[[page N]]` line per page, a question stopped by an input guard produced zero provider requests. With the fake provider the harness uses `KeywordModerationClassifier` (the container fake moderation returns null).
- Command `ai:evaluate` (alias `ai:eval`): `--suite`, `--provider=fake|configured`, `--allow-real`, `--threshold=name=value` (repeatable), `--report=path` (default `storage/app/ai-eval/report.json`), `--json`, `--no-store`. Exit 0 pass, 1 below threshold, 2 invalid option/dataset/provider. Stores one `ai_eval_runs` row (provider, prompt_version, metrics JSON with scores and counts only, `result` pass|fail) unless `--no-store`. `configured` needs `--allow-real` or `AI_EVAL_ALLOW_REAL` (config `ai.eval.allow_real`) and a healthy provider.
- CI: `.github/workflows/quality.yml`, job `bootstrap`, after `migrate --seed` and the Horizon check: step `php artisan ai:evaluate --provider=fake --report=...` (fails the job below thresholds) and an `upload-artifact` step for the JSON. It runs on every push and pull request (not label-gated, so it covers the `ai` label case too).
- Console: `app/Domain/AI/Console/TestConsoleAccess.php` (user active, `lesson_document.upload`, policy `update` on the course = manage-scope instructor or admin panel) and `Actions/AskInTestConsole` (final): resolves the lesson's active READY document, builds context, runs the sandbox, throttles at `ai.console.per_minute` (10), writes exactly one audit `ai.console_asked` (subject = lesson; context ids, status, guard, tier, `sandbox: true`; never the question or answer). Throws `AuthorizationException`, `AssistantRefused` (no approved document / no prompt) or `ValidationException` (empty or over-long question, throttled).
- Page `App\Filament\Pages\AssistantTestConsole` at `/admin/assistant-test-console` and `/instructor/assistant-test-console` (nav "Assistant test console" / "وحدة اختبار المساعد"). ## Acceptance
- A1 The evaluation command outputs metrics and fails below thresholds. `Artisan::call('ai:evaluate', ['--no-store' => true, '--report' => $tmp])` returns 0, the JSON has `result: pass`, `provider: fake`, `scripted: true`, `cases` equal to the case count in `cases.json`, and for `grounded_rate`, `refusal_correct_rate`, `length_compliance`, `red_team_pass`, `age_tier_pass` a `value` of 100 with `status: pass`; `latency.gated` is false and `manual.arabic_answer_quality.status` is `manual`. `--threshold=grounded_rate=101` returns 1 and the report says `fail`; `--threshold=bogus=1` and `--suite=nope` and `--provider=other` return 2; `--provider=configured` without the opt-in returns 2 and, with `--allow-real` while the container provider is `NullAiProvider`, returns 2 (never a real call). `--suite=ar` runs only `lang=ar` cases, `--suite=red-team` only red-team categories (other metrics `skipped`, not failed); `--suite=all` with a metric that has no case fails (point the loader at a temp dataset or delete the cases of one category through a temp copy). Storing: without `--no-store` one `ai_eval_runs` row with provider `fake`, `prompt_version` 1, `result` pass and `metrics` JSON that contains no question or answer text (grep the JSON for a question string). Break a guard to prove the gate: bind a `ModerationClassifier`-independent change is not possible, so instead mutate a case in a temp dataset copy (expect `outcome` wrong) and assert the run fails, lists the case id under `failed_cases` and returns 1. Dataset sanity: every case id unique, every `source` exists, both languages present with at least one case in each category, every `expect.pages` page exists in its source; PII cases never leave the raw value in any provider request (read `RecordingProvider::requests()` through a run, or assert the `not_sent` expectations pass); injected-source cases leave `[[page 99]]` out of the prompt and exactly one `</lesson_source>`. Leak regression: an answer that repeats rule 8 of the prompt is rejected with `GuardFailure::Leakage` (OutputGuard through `AssistantEngine::request` rules).
- A2 Console traffic is excluded from usage reports and quotas. Before and after one console question (answered, not_in_source and a guard-blocked one such as an injection phrase), counts of `ai_conversations`, `ai_messages`, `ai_usage`, `ai_quota_counters`, `ai_answer_cache`, `ai_safeguarding_flags` and `help_requests` are unchanged; the student's `AssistantEligibility::check` result (quota counters read) is unchanged; exactly one new `activity_log` row per question with `event = ai.console_asked`, `subject_type` Lesson, `properties.context.sandbox = true`, ids only (the question and answer text are not in the row). A self-harm phrase in the console raises no flag. Repeating the same question twice calls the provider twice (no cache read or write). The console works with the assistant off: global flag off, `ai_enabled` false on course and item, no consent anywhere.
- Authorization: the manage-scope instructor and an admin may ask; an instructor of another course, a view-scope instructor, a student, a parent and a suspended instructor get `AuthorizationException` from the action and nothing is written (no audit row); the page returns 403 for a student and renders the empty state (`[data-test-console-empty]`) for an instructor with no ready document; the lesson picker lists only lessons the user may test (another course's lesson id posted to `ask` yields the "choose a lesson" error, never an answer). Question validation: empty and 301 characters are refused with the lang message and write no audit. Throttle: the 11th question in a minute is refused (`ai.quota.rate_limited`).
- Page (Livewire test of `AssistantTestConsole`): the banner text (`ai.console.banner_body`) is always visible, the result card carries the "Test only" badge, the answer, cited page chips (`ai.source_page`), the supporting quote and the guard results for an answered case; a provider-not-configured run (bind `NullAiProvider`) shows the `ai.console.provider_failures.provider_error` line and the fallback message, never a stack trace; user text elements carry `dir="auto"`.
