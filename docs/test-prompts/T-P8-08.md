## Acceptance
- A1 Plan grants only included courses: a paid plan order gives the learner access to every included course and to no other `subscription_only` course; entitlements have source `subscription`, ref `subscription_period:<id>`, `starts_at` = period start and `ends_at` = period end + 3 days; running the grant twice, a replayed webhook or approving twice adds no second period or entitlement; a plan built from a category contains only that category's subscription/both courses; a parent paying for a child gives the child (not the parent) access.
- A2 Each reminder sent once: with `Carbon::setTestNow` at 6 days before the period end `SendSubscriptionRenewalReminders` sends one notice (offset 7) and a second run sends nothing; at 2.5 days one for offset 3, at 12 hours one for offset 1; three reminders over the period, each with its own `subscription_reminders` row; the notice goes to the payer in the payer's locale (AR and EN), mentions the plan and date; none for a cancelled subscription, for a period already renewed, for an ended period, or for an offset that passed before the period began; a payer who opted out of the optional event gets none; a failing send leaves no row and the next run delivers.
- A3 Expiry leaves individually purchased courses intact: a learner holds course X by purchase (and one by bundle) and course Y by the plan; after period end the plan course still opens during the 3 grace days, after grace it is denied and its entitlement is `expired`, while X stays allowed; `ExpireSubscriptions` marks the subscription `expired` once (audit and event), a second run does nothing; progress, submissions and certificates rows are untouched; a paid renewal after expiry restores access to the plan courses and the earlier progress is still there.
