## Cases to cover (minimum)
**Marking**
1. Admin and the managing instructor can mark; an instructor of another course, a learner and a parent cannot (`AuthorizationException`).
2. Refused while the session is `scheduled` or `cancelled`; allowed when `open` and `completed`.
3. Refused for a learner outside the audience: no entitlement, ended entitlement, cohort session without a seat, waitlisted or removed cohort member.
4. Invalid status value refused; note is trimmed and cut to 500; a second mark on the same learner is refused (`live.attendance.already_marked`); the unique index holds.
5. Audit row `live_attendance.marked` exists with learner id and status.

**Correction**

7. After a correction: status, source manual, marked_by, marked_at, note updated; audit `live_attendance.corrected` keeps the BEFORE status and the reason; two corrections give two audit rows in order.
8. A join-sourced row can be corrected and then reads as manual.
9. Permission matrix as in case 1.

**Join recording**
10. POST `/learn/{course}/{item}/join` inside the window creates one row: present; at start+10min exactly present, at start+11min late (use `travelTo`); a second join keeps the first row; an existing manual `absent` is never overwritten by a join.
11. A refused join (no access, outside window, cancelled, no link) creates no row.
12. Changing `live.late_after_minutes` with `config([...])` changes the boundary.

**Replay**
