## What was built
- `resources/views/components/learning/assistant-panel.blade.php` (`<x-learning.assistant-panel :lesson :pdf-url>`) and `assistant-opener.blade.php`, used in `resources/views/learn/show.blade.php`. The panel is `<aside id="ai-panel" data-ai-panel data-ai-slot>`; it is rendered only when `$aiAvailable` (eligible learner, recorded lesson, READY document, flag on). The opener `[data-ai-open]` sits in the player toolbar (video/audio lessons). At `2xl` and up the panel is a 24rem column that is always visible; below that it is a bottom sheet (`data-open="true"` shows it, `[data-ai-close]` and Escape close it and return focus to the opener).
- `resources/js/assistant.js` (imported in `app.js`). Opening pauses `[data-player-media]` and shows the timestamp chip (`[data-ai-timestamp]`, `ai.timestamp`). `GET .../assistant` supplies starter chips (`[data-ai-starter-list] button`, approved key terms: click fills the input, does not send). Submit (button or Enter; Shift+Enter = newline) POSTs JSON `{mode, question, video_position, conversation_id}` to `route('assistant.ask')` with the CSRF header, reads the SSE `token` events into the answer bubble, then the `result` event replaces the text with the validated message and renders page chips (`a[href$="#page=N"]`, `aria-label` = `ai.open_source_page`, plain span when there is no PDF url). Counter `[data-ai-counter]` counts code points (`ai.characters`), input `maxlength` = `config('ai.question_max_chars')`.
- `data-state` on the panel is the state machine: `idle`, `loading` (skeleton, `aria-busy`), `streaming`, `answer`, `not_in_source`, `out_of_scope`, `fallback` (retry button), `quota` (429 text + reset time, input disabled), `disabled` (403/409 reasons, or `available:false` from GET: message from the server, input disabled), `error` (422, network failure with retry, thread/simpler limit notices). Notices render in `[data-ai-notice]` (`role="alert"` for errors). A hidden `[data-ai-announce]` `role="status"` announces loading and "answer ready"; the streaming text itself is not a live region.
- Actions `[data-ai-action=understood|simpler|still]` appear after an answer. `simpler` sends `mode=simpler` with the `conversation_id`, once per question (re-enabled by the next normal question). `understood` and `still` are **disabled placeholders** with the hint `ai.panel.feedback_soon`: the feedback and help-request endpoints belong to T-P7-04. The hook is `data-feedback-url` (empty).
- Lang keys: new `ai.panel.*` in AR and EN (existing `ai.*` keys are reused).
- Not built (by task design): follow-up chips (ED-009 optional, not in the task steps), "request created" state (needs T-P7-04), the player toolbar entry for lessons without a video/audio toolbar.

## Also cover
- Pause and timestamp: with a loaded video seeked to 74 s, opening pauses it (`paused === true`) and the chip shows `ai.timestamp` with `1:14`; the POST body has `video_position` 74; pausing again at another time while the panel is open updates the chip. Audio lessons work; lessons without media show no chip and send `video_position` null.
- Streaming: tokens append in order; the final text equals the `result.message`; `source_pages` `[1]` renders one page chip linking to `<pdf>#page=1`, opening in a new tab with `rel=noopener`; the chip text is a localized page number (Arabic digits in AR if the locale formats so). HTML in an answer or question (`<img onerror>`) is shown as text (XSS check).
- Input: 300-char counter updates, 301st character cannot be typed, empty or whitespace-only submit shows `ai.panel.empty_question` without a request, Arabic and Latin text get `dir=auto`, a failed question stays in the field, a success clears it, retry after `fallback`/network error does not duplicate the user bubble.
- Thread: `conversation_id` from the first result is sent on the follow-up; thread limit (5th question, T-P7-01) shows the server message as a notice and keeps the panel usable; `simpler` once per question (second click impossible, server `simpler_limit` also handled), re-enabled after a new question.
- Quota 429: message `ai.quota_reached` plus `ai.panel.quota_reset` with a localized time; input and send disabled; panel does not crash with a missing `reset_at`.
- Player independence: with the assistant failing (503, offline) the video, progress calls, speed and fullscreen controls and next/previous still work; the page has no console errors.
- Placeholders: `understood` and `still` are disabled with the hint; when T-P7-04 lands these tests must be updated to cover the endpoint (note it as a TODO in the file header).
- Regression: `tests/Arch`, `app:check-translations`, `app:check-rtl`, group `T-P4-03`, `tests/Feature/Learning/CoursePlayerTest.php` (it asserts `data-ai-slot` is absent when unavailable), `npm run build`.
- Known gaps: no feedback/help-request wiring (T-P7-04); no input guard, quiz guard, cache or quota counters (T-P7-02, built elsewhere); the reply is a single provider call streamed after validation, so first token latency equals full answer latency.
