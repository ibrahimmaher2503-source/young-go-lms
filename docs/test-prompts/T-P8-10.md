## Acceptance
- A1 Statement: for a closed month with an earning (+10000), a reversal (-2500) and an adjustment, `GenerateInstructorStatement` stores earnings/reversals/adjustments/net equal to the ledger sums by type (compare with `LedgerTotals`), `entry_count`, snapshot lines (no student identity), `balance_forward_minor` = unpaid older entries (accrued/pending/approved/held; paid excluded), `settled_minor` = paid entries of the month, `closing = forward + net - settled`. Idempotent (same row returned, one audit `statement.generated`); current or future month gives `settlements.period_open`; bad format `period_invalid`; no entries `statement_empty`; non-instructor `instructor_invalid`; a later ledger change never alters the stored statement; the model refuses update and delete (`LogicException`). `system()` works without an actor (audit actor null). The command creates statements for every instructor+currency with entries, a repeat creates 0, an invalid period exits with failure. A `settlement.statement` notice is sent once per statement.
- A2 Batch creation: entries must all be `accrued`, exist and share the currency (`entries_invalid` / `entries_not_eligible`; held, pending, approved, paid or already batched entries are refused). Selected entries move to `pending`, amounts and every other column untouched. Per instructor net; item amount = net; batch totals/counts; reference `SET-YYYYMM-XXXXXX`. The same `$key` returns the first batch with no second audit; a second batch over the same entries fails. Needs `settlement.manage`: admin, support, student, inactive finance give `AuthorizationException`. Audit `settlement.created` with `carried_forward` in context.
- A3 Carry forward and readiness: an instructor whose selected net is zero or negative, or who has no payout profile (`PayoutReadiness`), is left out: their entries stay `accrued` and are listed in `carried_forward` (`not_positive` / `no_payout_profile`); a batch where nobody qualifies gives `settlements.nothing_to_settle`. Negative entries join a later batch and net against new earnings. No payout detail (holder, account, wallet) is read or written by these Actions or pages.
- A4 Approve / payout / cancel: approve moves `pending` to `approved` (idempotent, one audit); from other states `state_invalid`. Payout needs an approved batch, reference 3..64 chars, a method, a date not in the future; it moves that instructor's entries `approved` to `paid`, sets the payout fields, and the batch becomes `paid` only when every line is paid (two instructors: first payout leaves it `approved`); repeat with the same reference is a no-op (single audit), a different reference gives `already_paid`; notice `settlement.status` once per line. Cancel from draft/approved returns entries to `accrued`, keeps links and the row; refused after any payout (`state_invalid`); reason 5..500; cancelled entries can join a new batch. History: `Settlement` delete, `SettlementEntry` update/delete and a second `SettlementItem` payout write all throw `LogicException`; `LedgerEntry` still refuses any column change except status.
- A5 Hold / release: hold only `accrued` to `held` with reason 5..500 (`reason_invalid`); a repeat returns 0 and writes no audit; pending/approved/paid entries are refused (`entries_not_eligible`); held entries are excluded from batch creation and from `EligibleLedgerEntries`; release returns them to `accrued`. Audit per entry `ledger.entry_held` / `ledger.entry_released` with the reason in context.
- A6 Access and UI: finance and admin see statements and settlements (`ledger.view`); only finance sees generate/create/approve/payout/cancel/hold/release; the instructor panel lists only own statements; an instructor cannot open finance resources; the PDF route gives 404 for another instructor and a student, a login redirect for a guest, and 200 (or 503 without Chromium) for the owner and finance; `StatementPdf::data()` returns RTL/AR and LTR/EN variants, localized course titles and money strings; the Blade view renders for both locales. Pages render in AR and EN with RTL attributes.
