## Behavior to know before writing cases
- Start: needs `EntitlementService::canAccessItem` (else `NO_ACCESS`, controller answers 404); archived quiz refused; resumes an open attempt that is still inside time; an open attempt past deadline+grace is auto-submitted first; limit counts all attempts (started or finished); no active questions gives `no_questions`; deadline = start + time limit.
- Save: only the owner; only open; after deadline+grace the attempt is auto-submitted and `EXPIRED` is thrown (HTTP 409 JSON `{saved:false, closed:true}`); an answer must name a question of the attempt and option keys of the snapshot; single and true_false allow at most one key; text max 500 (short) or `assessment.max_text_length`; empty answers delete the stored row.
- Submit: idempotent (second submit returns the first result); answers sent with a late submit are ignored (only saved answers count) and `submitted_by = auto`; grading from the snapshot; written essay sets `needs_review` and `passed = null`; empty essay is 0 points without review; `passed` null when no pass mark; progression: `after_submission` completes the item on submit, `require_pass` only when `passed === true`.
- Results (`QuizAttemptView::result`): `full` shows score, pass state and per question the learner answer, correct options, accepted answers and explanation; `score_only` only the totals; `hidden` shows nothing until `released_at` is set. Open attempts never expose `is_correct`, explanation, accepted answers or points awarded.
- OPEN owner decisions in force: O-021 visibility values, O-022 pass mark as percent of total, O-023 no partial credit for multiple choice.

## Acceptance
- A1 Submit after the deadline is rejected or handled automatically.

- A3 Editing questions later does not change past attempts.

## Cases to cover (minimum)
**Start and limits (A2)**
1. Entitled learner starts: attempt 1, `deadline_at` = start + time limit (null for untimed), `snapshot` has only active questions, `total` = sum of points, audit `quiz.attempt_started`.
2. Starting again while open returns the same attempt (no second row). After submit, a new start creates attempt 2. With `max_attempts = 2` the third start is refused (`attempts_exhausted`, HTTP redirect with `quiz_error`); an auto-submitted or expired attempt counts; `max_attempts` null is unlimited; a learner never gets another learner's count.
3. Refusals: no entitlement, ended entitlement, draft/unpublished quiz item, unpublished section, drip-locked or sequence-locked item (all 404 for strangers via HTTP, `NO_ACCESS` in the Action), archived quiz, quiz with no active questions (`no_questions`), deactivated questions excluded.
4. A parent acting as a child (`ActingLearner`) starts and the attempt belongs to the child.
5. `QuizOverview::for`: questions count, total marks, attempts left, `can_start`.

**Deadline (A1)**

7. Submit before the deadline: `submitted_by = learner`. Submit after deadline+grace: late answers ignored, previously saved answers graded, `submitted_by = auto`. Boundary at exactly deadline and deadline+grace (change `assessment.grace_seconds` with `config()` too).
8. `ExpireQuizAttempts`/`quiz:expire-attempts`: closes only open timed attempts past deadline+grace, leaves untimed and still-valid ones, is idempotent, one failing attempt does not stop the others (mock a throwing case), reports the count. Check it is in the schedule (`routes/console.php`).
