## Acceptance tests to write
**Application (YG-GAP-INS-001)**
1. Guest sees `/teach` with sign-in/register CTAs (state `guest`) and cannot POST (redirect to login). Locale AR/EN both render.
2. Verified adult user submits the form: row `pending`, `pending_user_id` set, ID file stored on the private disk under `instructor-applications/` with a random name, never reachable from a public URL, audit `instructor_application.submitted` with no name/phone/links in values.
3. Refusals (ValidationException key `application`): unverified email, child account (email null), parent in child-context, user already holding `instructor_academy`/`instructor_independent`, second pending application (also the DB unique `pending_user_id` under a simulated race).
4. Validation: name/discipline/bio length, years 0..70, invalid Egyptian phone, 0 links, more than `max_portfolio_links`, non-http(s)/`javascript:` links; ID doc: too big, wrong content type (renamed .exe), encrypted/active-content PDF, image re-encoded (no EXIF); on any failure no file is left behind.
5. Spam: filled honeypot field `website` stores nothing and still redirects with the success notice; the throttle `instructor-application` returns 429 after `contact.rate_limit.per_minute` posts from one IP.
6. Privacy checkbox `privacy` required.

**Review (admin)**
7. Admin (`instructor.manage`) approves through the Filament table action (`ApproveRejectAction`): application `approved`, `pending_user_id` null, reviewer/time set; applicant gains `instructor_independent` (existing roles kept); a DRAFT `InstructorProfile` exists with unique slugs and is NOT public (`PublicInstructors`); audits `user.roles_changed` (before/after roles), `instructor_profile.saved`, `instructor_application_review.approved`; event `InstructorApplicationReviewed` dispatched after commit. Approving twice is a no-op (no duplicate role audit/profile). Existing profile is not duplicated.
8. Reject needs a reason (10..1000 chars): status `rejected`, `pending_user_id` freed so the user can apply again, audit `instructor_application_review.rejected` with reason; no role granted. Rejecting an approved application / approving a rejected one is refused.
9. Authorization: users without `instructor.manage` (finance, support, instructor) get 403/404 on the resource and the ID document route; document download sends `Cache-Control: private, no-store`; a missing file is 404; applicant cannot download their own.
10. A failing mutation rolls back role grant, profile and audit together (transaction).
