### T-P7-01 — Assistant core pipeline and output guard
- deps: T-P3-09, T-P3-10, T-P4-03
- agents: implementer, test-writer
- size: L
- risk: high
- ai: core — AI spec §5, §7, §8.2, §9
- refs: AI spec §5, §7, §8.2, §8.4, §8.5, §9, §17, PRD §15.2, PRD §15.4, PRD §15.6, ED-009, AI spec §4, AI spec §19
- gates: G1-G6, G8

**Goal** A question in an eligible lesson returns a verified, short, cited answer — or a correct `not_in_source`/`out_of_scope` — streamed to the client.
**Steps**
1. Endpoint `POST /api/v1/lessons/{lesson}/assistant/messages` + `GET .../assistant`; resolve lesson server-side; eligibility check.
2. Context builder: full-context mode (page-tagged approved text, cacheable prefix keyed by document_version) vs chunked mode above threshold (scoped retrieval).
3. Prompt from active `ai_prompt_versions` + style tier + reply language + last 2 turns.
4. Provider call (stream) with 15 s timeout; JSON schema validation; length caps; citation page existence; **quote verification** (normalized fuzzy match on cited page); one retry; safe fallback.
5. Buffer provider output server-side until schema, safety and citation checks pass; re-check current access/document version before delivery, then emit only verified result text (ED-036). Persist status, pages, quote_verified, prompt_version, model and usage; never stream unverified tokens.
6. Re-check entitlement + document status immediately before prompt construction.
**Acceptance**
- A1 Answer with verified quote shown; unverified quote never shown (tests with fake responses).
- A2 Other lesson's text never in prompt even if client sends another lesson id (test asserts fake provider request).
- A3 Provider timeout/error returns fallback state; player unaffected (test).
- A4 Over-length answer trimmed or retried per spec (test).
**Out of scope** Input guards, cache, quota (T-P7-02); UI (T-P7-03).

### T-P7-02 — Input guards, quiz guard, cache and quotas
- deps: T-P7-01, T-P6-02
- agents: implementer, test-writer
- size: M
- risk: high
- ai: core — AI spec §8.1, §8.3, §10
- refs: AI spec §8.1, §8.3, §10, O-015, O-028, PRD §5.3, PRD §15.6, ED-010
- gates: G1-G6, G8

**Goal** Safe, fair and cost-controlled assistant usage.
**Steps**
1. PII masking (phones, emails, national IDs, own name) before provider; opaque student hash.
2. Moderation classification (through adapter; fake in tests) → redirect message or safeguarding route (flag + fixed message; recipients/wording O-028; minors AI off until approved).
3. Injection heuristics → scope reminder.
4. Active-quiz guard: similarity of normalized question vs open graded quiz questions for the learner (keys never used) → page hint + `quiz_guard` event.
5. Per-lesson answer cache (document_version + normalized question + language + style tier; TTL 30 days).
6. Quotas: per student/day, per student/lesson/day, course and global budgets with 80% alert and graceful disable; `429` with reset time.
**Acceptance**
- A1 Phone/email in question never reaches fake provider (test).
- A2 Question matching an open quiz item does not get a direct answer (test).
- A3 Cache hit skips provider and is invalidated by new document version (test).
- A4 Quota exhaustion returns 429 and UI state (test).
**Out of scope** Semantic cache.

**Additional integration acceptance** ED-036: bind history to authenticated learner + lesson + document version; never reuse personalized conversation context across users. Cache only approved non-personalized answers with all eligibility/version keys, recheck guards on hits, and atomically reserve quota before provider work. Test cross-user/history spoofing, stale cache, concurrent quota exhaustion and revocation before delivery.

### T-P7-04 — Feedback, help requests and instructor/admin queue
- deps: T-P7-03, T-P5-04
- agents: implementer, ui-builder, test-writer
- size: L
- risk: high
- ai: core — AI spec §12
- refs: AI spec §12, PRD §16, D-019..D-021, Checklist §9, PRD §15.5
- gates: G1-G7

**Goal** "Still not understood" creates one help request routed to the responsible instructor with admin copy, resolved inside a platform thread.
**Steps**
1. `help_requests` (unique `ai_message_id`), `help_request_messages`, `help_request_events`; states New → In Progress → Instructor Replied → Waiting for Student → Resolved → Closed.
2. Feedback endpoint (understood/not_understood) idempotent; max 3 open requests per student per lesson.
3. Routing: responsible instructor for course/lesson, else admin queue; notifications (in-app; email optional).
4. Instructor queue (Filament instructor panel) with context: question, AI answer, cited pages, timestamp jump link, PDF page link, reply templates.
5. Admin view of all requests with reassign/intervene; SLA escalation job (default 24 h) marking overdue + admin notice.
6. Student thread UI (`help-request-thread`); parent sees status/replies per policy only.
**Acceptance**
- A1 Understood creates no request; repeated not-understood taps create one (tests).
- A2 Instructor of another course cannot see request (test).
- A3 Overdue escalation fires once (test).
- A4 Screenshots of student thread and instructor queue AR/EN.
**Out of scope** "Mark as lesson FAQ" (O-AI-01).
