### T-P8-03 — Paymob webhook verification and idempotent fulfillment
- deps: T-P8-02
- agents: implementer, test-writer
- size: M
- risk: high
- ai: hook — entitlement grant/revoke immediately changes AI eligibility (no caching beyond request)
- refs: YG-GAP-PAY-002, PRD §23 (3,4), Arch §10.2, Checklist §10, §14A
- gates: G1-G6, G9

**Goal** Only a verified Paymob callback fulfills an order, exactly once.
**Steps**
- [ ] `/webhooks/paymob` with signature verification middleware; store `payment_webhook_events` (unique event/transaction id).
- [ ] Match merchant order ref, amount, currency, success state; mark paid; emit `PaymentVerified` once.
- [ ] Listener grants entitlements per order item via `GrantEntitlement` (source purchase/bundle/subscription) and reserves cohort seat when applicable; creates ledger source events (consumed by T-P8-09).
- [ ] Invariant tests I03 (pending/failed never grants), I04 (one verified payment fulfills once).
**Acceptance**
- [ ] A1 Tampered signature rejected (test).
- [ ] A2 Amount/currency mismatch rejected and flagged (test).
- [ ] A3 Duplicate/replayed webhook → one entitlement, one ledger source (test).
**Out of scope** Refunds.
