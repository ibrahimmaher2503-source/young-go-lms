**Goal** Server-calculated orders with immutable totals and payer/learner separation.
**Steps**
1. `orders` (payer_id, market, currency, subtotal, discount, total minor units, status pending/paid/failed/cancelled/refunded/partially_refunded/disputed, idempotency key), `order_items` (product type course/bundle/plan, product id, learner_id, unit price snapshot, allocation fields).

- A2 SA market order rejected (test).

**Review requirement — YG-REV-PAY-001 (PRD §29.15)**

Use integer minor units and deterministic rounding; server revalidates offer eligibility and coupon constraints atomically. Edits affect new checkouts only.

**Additional acceptance** Tampered learner/price/currency, zero/negative totals, expired coupon, last coupon use concurrently, changed price/bundle/commission during payment; line/discount/tax/allocated totals reconcile exactly. Zero-value orders require no fabricated gateway payment. Evidence is required; this task remains todo until implemented and verified.

### T-P8-03 — Paymob webhook verification and idempotent fulfillment
- deps: T-P8-02, T-P5-01
- agents: implementer, test-writer
- size: M
- risk: high
- ai: hook — entitlement grant/revoke immediately changes AI eligibility (no caching beyond request)
- refs: YG-GAP-PAY-002, PRD §23 (3,4), Arch §10.2, Checklist §10, §14A
- gates: G1-G6, G9

**Goal** Only a verified Paymob callback fulfills an order, exactly once.
**Steps**
1. `/webhooks/paymob` with signature verification middleware; store `payment_webhook_events` (unique event/transaction id).
2. Match merchant order ref, amount, currency, success state; mark paid; emit `PaymentVerified` once.
3. Listener grants entitlements per order item via `GrantEntitlement` (source purchase/bundle/subscription) and reserves cohort seat when applicable; creates ledger source events (consumed by T-P8-09).
4. Invariant tests I03 (pending/failed never grants), I04 (one verified payment fulfills once).
**Acceptance**
- A1 Tampered signature rejected (test).
- A2 Amount/currency mismatch rejected and flagged (test).
- A3 Duplicate/replayed webhook → one entitlement, one ledger source (test).
**Out of scope** Refunds.

**Review requirement — YG-REV-PAY-002 (PRD §29.15)**
Persist verified provider events durably before acknowledgement; one provider transaction cannot satisfy two orders. Idempotent local fulfillment covers payment, grants, enrollment and ledger; notifications use retry-safe post-commit delivery. Stale failure/paid events cannot downgrade or resurrect refunded/disputed records; uncertain states reconcile with the provider.

**Additional acceptance** Invalid signature/environment/merchant/amount/currency/reference; duplicate/reordered success/failure/refund; database/job interruption; duplicate manual approval; payment retry with a second provider transaction. No double charge claim or fulfillment; excess payment is visible for finance resolution. Evidence is required; this task remains todo until implemented and verified.

**Goal** Idempotent ledger entries from verified commercial events per the simple approved rules.

**Review requirement — YG-REV-FIN-001 (PRD §29.15)**
Store source and effective version of each commission/rate/allocation and instructor assignment. Allocate whole minor units deterministically with totals conserved. Fixed subscription earning is unique per eligible learner/course/period. Settled entries are immutable; subsequent reversals create adjustments/debt for finance review, never silently rewrite paid history.

**Additional acceptance** Rate/instructor changes after sale; bundle remainder; mixed discounts/tax; retry/double settlement; subscription duplicate; refund before/after payout. Approved statement + adjustments reconcile to collections and settlement references. O-008..O-012/O-031/O-032 must be resolved for affected live offers. Evidence is required; this task remains todo until implemented and verified.
