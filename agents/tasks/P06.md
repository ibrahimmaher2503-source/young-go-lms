# P6 — Quizzes, practical assignments & certificates

### T-P6-01 — Quiz authoring and question bank
- deps: T-P3-11
- agents: implementer, ui-builder, test-writer
- size: M
- risk: normal
- ai: hook — expose open graded questions (text only, no keys) to the quiz guard query
- refs: PRD §12, Checklist §8
- gates: G1-G7

**Goal** Instructors build quizzes with supported question types and settings.
**Steps**
1. `questions` (type single/multiple/true_false/short_answer/essay, prompt translatable, points, explanation, order, active, version), `question_options` (text, is_correct, order).
2. Quiz settings: time limit, total marks, pass mark, max attempts, result visibility, randomization flag, progression (after submission / require pass).
3. Filament authoring UI with preview.
**Acceptance**
- A1 Validation per type (e.g. single-choice exactly one correct) (test).
- A2 Instructor scoped to assigned courses (test).
**Out of scope** Runtime.

### T-P6-02 — Quiz runtime and attempts
- deps: T-P6-01, T-P4-04, T-P4-09
- agents: implementer, ui-builder, test-writer
- size: L
- risk: high
- ai: hook — while an attempt is open, quiz guard is active for that learner
- refs: PRD §12, Roadmap M6.1, Checklist §8
- gates: G1-G7

**Goal** Learners take quizzes with server-enforced time, attempts, scoring and gating; history immutable.
**Steps**
1. `quiz_attempts` (snapshot of questions/options at start), `quiz_answers`.
2. Start/save/submit Actions; server timer (deadline at start); auto-submit on expiry; scoring; pass/fail; progression gating.
3. Result page respecting visibility; correct answers hidden until allowed; quiz-question and quiz-timer components.
**Acceptance**
- A1 Submit after deadline rejected/auto-handled (test).
- A2 Attempt limit enforced (test).
- A3 Editing questions later does not change past attempts (test).
- A4 Correct keys never sent to client before allowed (test inspects payload).
**Out of scope** Essay grading UI (T-P6-04 handles review queue).

**Review requirement — YG-REV-LRN-002 (PRD §29.15)**
Quiz attempt creation/submission, timing and attempt limits are server-authoritative and concurrency-safe; submission retries produce the same result. Snapshot questions/scoring; deadline, late submission, manual grading/regrading and assignment revision rules remain explicit. A client timeout is not a second submission.

**Additional acceptance** Two tabs consume final attempt once; reconnect at deadline; repeated submit; grade correction recalculates eligibility without erasing history; forbidden file/path; late assignment and revision limit. Access loss during an attempt produces a defined denial/recovery state without deleting saved work. Evidence is required; this task remains todo until implemented and verified.

### T-P6-05 — Completion engine
- deps: T-P6-02, T-P6-04, T-P5-05
- agents: implementer, test-writer
- size: M
- risk: high
- ai: none — add nothing AI-related
- refs: PRD §14, O-020
- gates: G1-G6

**Goal** Configurable course completion rules evaluated by events.
**Steps**
1. Course completion config: lesson %, required quizzes passed, required assignments accepted, attendance %, manual approval.
2. Evaluator listens to progress/quiz/assignment/attendance events; marks completion idempotently; manual override audited.
**Acceptance**
- A1 Each rule combination evaluated correctly (dataset test).
- A2 Duplicate events do not duplicate completion (test).
**Out of scope** Certificate rendering (T-P6-06).

**Review requirement — YG-REV-LRN-001 (PRD §29.15)**
Record the curriculum/completion-rule version used for completion and certificates. Adding/reordering/archiving content never erases attempts, progress or issued certificates; explicitly revoke/void when authorized. Required-item changes show impact before publication; courses with zero required items do not auto-certify.

**Additional acceptance** Completed learner + new required item; archived quiz with attempts; changed pass threshold; duplicate completion jobs; renewal after expiry; certificate reprint after name correction. Original completion basis stays traceable. Evidence is required; this task remains todo until implemented and verified.

### T-P6-06 — Certificates and verification
- deps: T-P6-05, T-P1-02
- agents: implementer, ui-builder, test-writer
- size: M
- risk: high
- ai: none — add nothing AI-related
- refs: PRD §14, YG-GAP-ID-001, R-030, Checklist §8
- gates: G1-G7

**Goal** Branded bilingual certificates issued once on completion with public safe verification.
**Steps**
1. `certificate_templates` (language, HTML/Blade layout using tokens, issuer text placeholder O-019), `certificates` (unique number, token, status, revoked_at).
2. `PdfRenderer` (headless Chromium) with correct Arabic shaping; QR to verification URL.
3. Issue on completion (idempotent); lock certificate names; revoke/void audited.
4. Public verification page showing only safe fields; revoked shows invalid.
**Acceptance**
- A1 One certificate per learner/course even on repeated events (test).
- A2 Arabic name renders correctly (visual snapshot of PDF page in screenshots).
- A3 Verification page exposes no email/phone (test).
**Out of scope** Final legal wording (O-019).
