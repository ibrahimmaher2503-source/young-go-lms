### T-P3-09 — Curriculum PDF ingestion pipeline (M7.1)
- deps: T-P3-08, T-P3-10
- agents: implementer, ui-builder, test-writer
- size: L
- risk: high

- refs: AI spec §6 (all), §14 readiness indicator, ED-011
- gates: G1-G7, G8
- visual: [Curriculum builder](../../docs/design-system/reference-pack-2026-11-17/03-curriculum-builder.png), [Component board](../../docs/design-system/reference-pack-2026-11-17/18-shared-component-library-v2.png) · [Implementation and match](../../docs/design-system/reference-pack-2026-11-17/IMPLEMENTATION.md)

**Goal** Uploaded lesson PDFs become approved, page-tagged, quality-checked text ready for the assistant.
**Steps**
- [ ] Queued job: extract text per page; Arabic repair (NFKC, presentation forms, reversed lines, repeated headers/footers).
- [ ] OCR fallback per failed page through `OcrProvider` (fake in tests).
- [ ] Quality score per page/document with thresholds in config; FAILED with readable reason.
- [ ] Approval UI: side-by-side page image vs extracted text, edit text (versioned, audited), approve → INDEXING → READY; chunking + embeddings only when > threshold tokens.
- [ ] Key terms extraction (3–8 terms appearing in text) + instructor approval.
- [ ] Readiness indicator in curriculum manager (⚪🟡🟠🔴🟢).
**Acceptance**
- [ ] A1 Fixture Arabic PDF with presentation forms is repaired to valid words (test).
- [ ] A2 Scanned fixture page triggers OCR path (test with fake OCR).
- [ ] A3 Only approved text becomes the active source; replacement swaps atomically (test).
- [ ] A4 Injection text inside PDF stored as data only (red-team fixture saved for T-P7-05).
- [ ] A5 Screenshots of approval UI AR/EN.
- [ ] G7 (when UI is in scope): capture the implemented screen, compare it with the task reference, and record the result. Resolve unexplained visible differences before closure.
